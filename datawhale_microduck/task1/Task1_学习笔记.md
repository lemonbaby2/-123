# Task1 学习笔记：MicroDuck 篮球平衡中的模型、观测、动作与 PPO

## 一句话理解

MicroDuck 并不是接收“保持平衡”这个抽象指令后直接站稳，而是在 50 Hz 闭环中不断重复：读取 61 维身体感觉，策略网络输出 14 个关节动作，MuJoCo 推进物理状态，再把新的状态交给下一次推理。

## 1. 模型

本任务的 actor 接收 61 维本体观测并输出 14 维关节动作。它不是只看一帧的普通 MLP，而是先经过 `LSTM(256)` 保存时序记忆，再经过 `512 → 256 → 128` 的 ELU MLP 得到动作。因为 actor 不直接读取篮球的位置与速度，LSTM 需要从连续的姿态、关节和上一动作中推断球的滚动趋势。

ONNX 契约为：

```text
obs  [1, 61]      ─┐
h_in [1, 1, 256]   ├─> actions [1, 14]
c_in [1, 1, 256]  ─┘   h_out/c_out [1, 1, 256]
```

每次推理后的 `h_out/c_out` 必须传给下一步；只有首次启动、切换策略、摔倒恢复或 episode reset 时才清零。

## 2. 观测

61 维观测是小鸭子当前的“全套身体感觉”：

| 范围 | 内容 | 维度 |
| --- | --- | ---: |
| `0:3` | 身体角速度/陀螺仪 | 3 |
| `3:6` | 身体坐标系下的重力投影 | 3 |
| `6:20` | 14 个关节位置 | 14 |
| `20:34` | 14 个关节速度 | 14 |
| `34:48` | 上一时刻动作 | 14 |
| `48:51` | 前向、横向、偏航速度命令 | 3 |
| `51:55` | 头部命令零填充 | 4 |
| `55:61` | 身体命令零填充 | 6 |

部署 actor 看不到球的真值状态，这使策略仍然是 blind/proprioceptive policy。训练阶段的 critic 可以额外读取球的位置、线速度、角速度和接触信息，从而更准确地估计价值；部署时只保留 actor，并不存在把训练答案泄漏给机器人的问题。

## 3. 动作

14 维动作分别对应 MicroDuck 的 14 个电机关节：左腿 5 个、颈部与头部 4 个、右腿 5 个。动作不是直接瞬移关节，而是进入执行器与 MuJoCo 接触动力学，改变落脚、重心和球的滚动。下一控制周期的新观测会反映这些动作造成的结果，因此稳定来自持续闭环修正，而不是某个固定姿势。

## 4. PPO 如何学会平衡

PPO 通过大量并行环境反复采样“观测—动作—奖励—下一状态”，再限制每轮策略更新幅度，避免一次更新把已学会的行为破坏得太严重。篮球任务的奖励同时考虑速度跟踪、身体直立、相对球心居中、双脚接触、根部高度、球速正则和动作变化。只惩罚球速会让策略学成僵硬站立；加入速度跟踪后，策略才会学习边换重心边让球按指令滚动。

训练早期还使用逐渐减弱的 hold curriculum：先在较容易的条件下学会站稳，再逐步放开篮球成为完全自由刚体。公开实现使用 privileged critic 帮助训练，而最终 actor 仍只依赖 61 维本体观测和 LSTM 记忆。

## 5. 本机仿真记录

我使用任务专属公开 `policy.onnx` 在本机重新运行了闭环仿真。Windows 下 MuJoCo-Warp 的 CUDA 物理 JIT 未能完成，因此采用 CPU 推进物理、RTX 4060 执行 LSTM ONNX 策略：

- 250 个控制步，控制频率 50 Hz，共 5 秒；
- 观测维度 61，动作维度 14；
- 全程 0 次终止或重置，连续稳定 5.0 秒；
- 平均策略推理 2.45 ms，P95 为 2.72 ms；
- 对真实仿真观测进行 32 次输出校验，最大绝对误差 `8.34e-7`。

这些数据说明模型接口、时序状态、关节动作和物理环境已经接成闭环。它是对公开策略的本机复现，不是从零训练，也不能据此宣称真机已经安全可用。

## 6. 学习心得（打卡表可直接填写）

这次 Task1 让我真正把“强化学习策略”理解成一个持续运行的控制闭环，而不是一次性生成动作。MicroDuck 每 20 ms 读取 61 维本体观测，LSTM 根据当前状态和历史记忆输出 14 个关节动作，动作经过执行器与 MuJoCo 接触动力学后形成下一帧状态。篮球本身不在 actor 的观测里，策略要从陀螺仪、重力投影、关节状态和上一动作中推断球的滚动趋势；训练时 critic 才额外使用球状态。PPO 的关键也不只是“摔很多次”，而是用速度跟踪、直立、居中、接触、高度和动作平滑等组合奖励约束目标，并用裁剪更新保持学习稳定。本机复现完成了 61→14 的 LSTM ONNX 闭环：250 步、5 秒、无重置，真实观测输出校验的最大误差为 8.34e-7。最大的收获是分清了训练、部署和仿真验证三件事，也知道不能把仿真生存率直接写成真机成功率。

## 7. 课程反馈（打卡表可直接填写）

课程用 61 维观测、14 维动作和篮球平衡场景把模型、观测、动作、PPO 串得很直观，Notebook 也明确区分了公开 checkpoint、本地复现与真机边界。建议后续再补一份 Windows 环境说明：课程默认的 Linux CUDA/EGL 路径在 Windows 上需要切换渲染与物理后端；同时可增加一个只做 ONNX 契约检查和 100～250 步短仿真的轻量入口，方便显存或系统环境有限的同学先完成闭环验证。
