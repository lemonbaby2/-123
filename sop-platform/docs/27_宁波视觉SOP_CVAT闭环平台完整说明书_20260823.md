## 2. 系统地址、账号角色与安全登录

### 2.1 服务地址

同一局域网内访问 `http://192.168.1.129:8112`。CVAT 使用 `http://192.168.1.129:8081`。实时归档流为 `rtsp://192.168.1.129:8554/cam0`、`cam1`、`cam2`，HLS 地址为 `http://192.168.1.129:8888/cam0/index.m3u8` 等。

### 2.2 三类账号

平台内置开发者、管理者和普通员工三种角色。首次随机密码保存在服务器独立运行目录的 `initial_credentials.txt`，权限为 `600`。该文件不进入 GitHub、公开压缩包、网页源码或操作截图。开发者可切换模型和系统配置；管理者可启动预标、导入、同步、训练和 MES 测试；普通员工只看到现场查看和必要标注能力。

### 2.3 登录操作

1. 打开 8112，输入线下发放的岗位账号和密码。
2. 登录成功后核对右上角显示的姓名和角色。
3. 若功能按钮缺失，先确认当前角色，而不是修改前端隐藏规则。
4. 操作结束后点击“退出”，共享工位浏览器不得长期保留管理员会话。
5. 正式公网或跨网段部署必须启用 HTTPS 和 Secure Cookie。

## 3. 总体业务闭环与职责边界

### 3.1 正式闭环

正式流程为：原始视频或相机流进入 VideoAsset；执行完整性、去重和代理生成；按固定工位标签模板进行 AI 预标；在 CVAT 中人工删除、移动、缩放、改类别、补框和修 Track；Reviewer 验收后形成 Annotation Version；Dataset Builder 关联原 MP4、标注和 Frame Manifest；训练、验证并登记 Model Version；实时 SOP 与设备证据共同决定 PASS、NG、REWORK 或 HOLD；误报、漏报、低置信度和稀有 NG 回到 Hard Case 队列。

### 3.2 禁止的捷径

- 不允许把 AI 候选直接当作人工真值进行正式训练。
- 不允许把全部工位的总标签池直接套到单一固定工位。
- 不允许把带框视频当成训练标签的替代品。
- 不允许按相邻帧随机拆分训练集、验证集和测试集。
- 不允许因页面显示模型名称就宣称模型已安装、已训练或已达到量产精度。
- 不允许把账号、Token、Webhook Secret、视频、权重、数据库或 WAL 推到公开仓库。

### 3.3 SOP 与 CVAT 的分工

SOP 平台负责视频资产、设备、工位标签口径、预标队列、数据集版本、训练任务、实时状态机和 MES 审计。CVAT 负责成熟的框、Polygon、Mask、Skeleton、关键帧、插值、Track、标注员协作和 Reviewer 工作流。两个系统通过 Task 绑定、API Token、项目作用域、HMAC-SHA256 Webhook、annotation-only 文件和 Frame Manifest 互联，而不是来回复制每一帧 PNG。

## 4. 01 总览页面

### 4.1 页面用途

总览集中显示平台服务、DGX、CVAT、MES、视频任务数、视觉证据帧、SOP 阶段、HOLD 状态、现场画面、当前处置、证据趋势、多模态链路和边缘设备。页面采用参考图的深色导航、白色工作区、低圆角密集面板，便于班组长快速扫描。

### 4.2 如何理解 HOLD

HOLD 是安全默认值，不等于系统故障。人工真值不足、Reviewer 未通过、设备回执缺失、MES 未 ACK、模型版本未验收或实时证据不完整时均应保持 HOLD。只有 SOP 顺序正确、视觉必需项齐全、设备门禁满足、质量规则通过且 MES 回执成功，才允许输出 PASS。

### 4.3 每班查看项目

先看视频任务和设备在线数，再看 CVAT 队列和待复核版本，最后查看 NG、REWORK、HOLD 和未闭环告警。趋势图只表示证据字段是否完整，不能解释为模型准确率。

## 5. 02 数据获取与清洗

### 5.1 支持的数据来源

页面支持 RTSP/UVC 实时源、Pocket 3 或 SD 卡只读介质、Google Drive 增量源和本地历史视频。导入时必须绑定工位、产品或 SN、日期和来源。原始文件只保存一次，浏览器不兼容或体积过大的视频生成 H.264 代理，原片绝不覆盖。

### 5.2 Pocket 3 和 SD 卡导入

当前 Pocket 3 以 exFAT 存储卷出现，因此只能只读导入，不能作为实时 UVC。页面列出视频文件、大小和时间，默认只选前三段。点击“导入选中视频”后，系统执行路径约束、`.part` 复制、大小核对、SHA256、原子改名、可解码检查、VideoAsset 入库、目录刷新和 AI 预标排队。页面每两秒读取真实任务状态，完成后自动刷新视频选择器，不再停留在“任务已排队”。

### 5.3 实时相机模式

Pocket 3 若要实时检测，必须切换到厂商支持的 Webcam/UVC 模式，并在 Linux 上出现稳定的 `/dev/video*` 或 `/dev/v4l/by-id/*`。平台不会向相机、SD 卡或固件写入渗透、驻留或传播脚本。正确的“记住设备”方式是主机侧设备登记、稳定路径、序列号、VID/PID 和受控配置。

### 5.4 完整性、去重和隔离

每段视频应检查时长、FPS、分辨率、编码、帧数和首尾可解码性。零长度、仍在写入、损坏、重复或路径越界的文件拒绝入库。来源文件 ID、大小、修改时间和内容摘要用于幂等识别。隔离区文件不能自动进入预标和训练。

### 5.5 Google Drive 17:00

系统保留 rclone OAuth 和 systemd timer 方案。17:00 只执行增量抓取、完整性检查、去重、入库和预标，不立即正式训练。Google 账号密码禁止写入脚本；首次由管理员执行 OAuth，验证 remote、文件夹权限、断点下载和日志后再启用 timer。当前页面显示“待 rclone OAuth”是正确状态。

## 6. 视频加载、媒体目录和播放健康

### 6.1 本次故障根因

旧实现把 `videos.json` 中的 `media/...` 路径假定为当前网页目录下文件，但新工作树没有完整媒体副本，导致大量 404。简单复制数百 GB 视频既浪费空间，也容易让不同版本的数据失去一致性。

### 6.2 新媒体解析方式

8112 使用受控多根目录解析器，依次查找当前网页媒体目录、新版本运行媒体目录、只读历史媒体库和管理员配置的额外根目录。路径必须是 `media` 下相对路径，拒绝绝对路径和 `..` 穿越。新导入文件进入独立运行目录，历史视频只读复用，不复制原片。

### 6.3 浏览器 Range 播放

普通请求和 `Range: bytes=` 请求使用同一解析器，返回正确 `Content-Type`、`Accept-Ranges`、`Content-Range` 和长度。健康接口逐条返回 `source_playable`、`presentation_playable`、`missing_media` 和总体数量。发布前必须逐条读取至少 1024 字节，并在浏览器检查 `readyState`、宽高和非黑画面。

#### 6.3.1 播放验收要点

不能只用首页 HTTP 200 作为验收。目录数量、Range 状态、实际字节数、浏览器元数据、画面像素和控制台错误必须同时检查；任一视频缺失时健康接口应明确列出，而不是让下拉框静默选择一个 404 地址。

## 7. 03 AI 预标注与现场证据

### 7.1 先人工建立工位口径

每个固定工位先人工标注数个完整 SOP 循环，覆盖正常动作、遮挡、反光、转向、速度变化、步骤边界和稀有 NG。标签模板必须写明必标、可选和当前阶段不标的对象。例如 PCB 插装工位可使用 PCB 板、治具、物料框、手持二极管、其他插件、插件位置、手部和异常零件，而不是加载所有产线标签。

### 7.2 全视频预标策略

预标脚本读取同一 VideoAsset 目录和独立 SQLite，按每 5 帧生成开放词汇候选。导入新视频后自动进入同一队列；中断后根据已处理帧继续。候选保存来源模型、置信度、框坐标、帧号、时间戳和 `pending` 状态。预标用于提高人工效率，漏检仍需人工补框。

### 7.3 现场证据处置

页面显示当前步骤、风险分、证据完备度、ROI、动态目标、小目标候选和缺失项。质量员可标记误报、需要返工或人工确认，动作会进入审计日志，但“人工确认现场处置”不自动等于 Reviewer 真值验收。

## 8. 04 网页逐帧标注

### 8.1 基本操作

选择视频后可播放、暂停、上一帧、下一帧、按指定数量跳帧或拖动时间轴。拖动鼠标画框，选择区域、工位细分类标签、轨迹 ID 和框颜色。保存当前框后，当前帧队列显示来源、置信度、审核状态和操作按钮。

### 8.2 关键帧和自动跟踪

在起始帧画框并设置起始关键帧，跳到后续帧，可移动结束框进行人工校正，再执行自动跟踪。遮挡、出画、重新出现、方向突变和步骤边界应增加关键帧。跟踪漂移时分段重建，不保留错误传播。删除支持单框、整条轨迹和轨迹区间，并保留删除审计。

### 8.3 自动保存与恢复

标注写入 SQLite WAL，保存进度时执行数据库 backup、视频硬链接或引用缓存，并生成压缩历史快照。浏览器刷新或异常退出后先点击“恢复自动缓存”，核对视频 ID、帧号、草稿框和保存轮次。服务运行时不能只复制 SQLite 主文件，避免遗漏 WAL 和 SHM。

## 9. CVAT 创建任务与人工复核

### 9.1 SOP 到 CVAT

在“当前整段视频创建标注任务”中确认当前视频、任务名和产线数据集，然后点击“创建并上传整段视频”。8112 使用 CVAT Project 5 和 `lan-team` 组织作用域创建任务，上传解析后的原视频或代理视频，并记录 SOP video_id 与 CVAT task_id 绑定。Task 1295 已完成该链路实测。

### 9.2 CVAT 中能否修改 AI 框

可以。AI 框进入 CVAT 后可删除、移动、缩放、改类别、补框、修改属性、调整关键帧和修正 Track。因此推荐“人工标几个完整循环 → AI 学习和预标 → 人工逐段复核 → Reviewer 验收”，不需要退回纯人工从零开始。

### 9.3 标注员操作

打开绑定 Task 和 Job，播放整段视频。逐段检查漏标、误标、框偏移、类别混淆和 Track 连续性。使用矩形、Polygon、Mask、Skeleton 或 Track 工具时遵守工位模板。保存后提交 Reviewer，不能自行把未复核任务标为生产真值。

### 9.4 Reviewer 操作

Reviewer 检查完整循环和 NG 稀有样本，重点看步骤边界、遮挡、反光和轨迹漂移。不通过时写明原因并退回；通过时记录审核人、时间和状态。手工从 SOP 拉取的版本只能是 `pending_review`，正式 `accepted` 只能由批准事件产生。

## 10. CVAT 到 SOP 的双向同步

### 10.1 Webhook 安全

CVAT Project 5 已配置指向 8112 的 Webhook，事件包括 Task/Job 更新和 merge 完成。SOP 使用 HMAC-SHA256 校验原始请求体，签名不正确直接拒绝。API Token、组织 slug 和 Webhook Secret 只保存在权限 600 的私有环境文件。

### 10.2 私网回调说明

CVAT 2.73 的 Smokescreen 会阻止私网 Webhook。精确私网 allow 规则在当前镜像构建中未生效，因此只对 `cvat_worker_webhooks` 启用了私网回调；SOP 端仍强制 HMAC 验签。没有关闭 CVAT 主服务的防护，也没有对其他 worker 扩大权限。真实 `update:task` 回调已返回 202。

### 10.3 Annotation-only 拉取

SOP 请求 CVAT 2.73 annotation API 时使用 `Accept: application/vnd.cvat+json`。返回内容限制最大字节数，保存原始 annotations JSON、标签映射、版本号、SHA256 和 Frame Manifest。Task 1295 已生成版本 `CVAT-1295-v0-...`。回流不复制每一帧图片，因此速度和容量明显优于 Dataset ZIP。

#### 10.3.1 版本验收要点

每次回流核对 task_id、video_id、CVAT version、annotation_count、SHA256、review_status 和 received_at。同一内容重复回调应幂等，不重复创建不同真值版本；失败任务保留错误原因，管理员修复后手工重试。

## 11. 三种客户导出格式

### 11.1 轻量标注 ZIP

推荐训练交接使用。内容包括 JSON、CSV、审核状态、数据集来源清单、少量证据截图和审计记录，不重复打包全部原视频。原 MP4 通过 video_id、文件名、SHA256 和 Frame Manifest 关联。

### 11.2 全帧带框 JPEG ZIP

客户需要逐帧检查时点击“生成全帧图片 ZIP”。后台逐帧读取视频、按标注绘框、缩放到最大 1280 宽度、JPEG 质量 82 编码，并写入 ZIP、manifest 和 annotations。该格式一定可能比 MP4 大，因为帧间压缩被展开；系统只能通过 JPEG、分辨率和生命周期控制容量，不能承诺与原视频一样小。

### 11.3 完整带框 MP4

点击“生成完整带框 MP4”后，后台逐帧绘制并使用 H.264、yuv420p 和 faststart 生成浏览器可播放成片，同时保存审计 JSON。它适合客户汇报和复核，不代替训练标签。实测 22.93 秒视频生成 344 帧 JPEG ZIP 约 27.3 MB，完整带框 MP4 约 3.54 MB。

### 11.4 下载进度

两个大导出均为异步任务，页面显示进度、结果大小和失败原因。完成后浏览器自动下载。生成过程中不锁死网页，也不修改源视频。导出目录应设置容量水位和清理周期。

## 12. 05 数据集构建与质量冻结

### 12.1 Reviewer 门禁

数据集页面只列出 Reviewer 已验收的 Annotation Version。`pending_review`、`rejected` 或普通 AI 候选不能构建正式数据集。用户选择版本、工位 ID 和产品族后点击“冻结数据集”。

### 12.2 Dataset Version 内容

冻结结果记录 dataset_id、annotation_version_id、CVAT task、原视频、Frame Manifest、标签映射、SHA256、创建时间、工位、产品族和拆分策略。此步骤不永久生成全量 PNG；训练开始时才按需生成 JPEG 缓存。

### 12.3 数据划分和质量检查

Train、Val、Test 必须按完整视频、产品 SN、工位或日期隔离，禁止把连续相邻帧随机拆到不同集合。检查类别分布、空标签、越界框、重复帧、路径、许可证和稀有 NG 数量。冻结测试集后任何修改都必须形成新版本。

## 13. 06 六模型训练、验证与部署

### 13.1 模型目录

- YOLO26N：生产实时基线，Ultralytics 训练执行器可用。
- YOLOE-26S + SAHI：开放词汇和小目标候选，预标流程可用。
- YOLOv8s-World v2：本机已有 Ultralytics 权重，已接入训练选择器，作为兼容和回归基线。
- RT-DETRv2：已有候选权重登记，完整训练后端待安装，适合 Shadow 或离线交叉验证。
- D-FINE：已有候选权重登记，完整训练后端待安装，重点比较边界和小目标。
- PatchCore/EfficientAD：用于划痕、污迹和涂料不均匀，完整训练后端待安装，适合事件触发 ROI。

### 13.2 正式训练步骤

选择已冻结数据集、模型和“仅人工确认真值”，设置 epochs、batch、输入尺寸、设备、workers、patience 和随机种子。启动后保存日志、环境、代码提交、基础权重哈希和 Dataset Version。候选预训练允许研究，但不得计入量产精度。

### 13.3 同条件验证

使用同一冻结测试集、同一硬件、同一输入尺寸、同一阈值和预热策略，输出 Precision、Recall、mAP50、mAP50-95、关键 NG Recall、每百件误报、P95 延迟、显存和长稳结果。新模型先单工位 Shadow，再灰度，并保留旧版本回滚。

### 13.4 运行策略

不应让六个模型全部 30 FPS 同时决定生产结果。建议 YOLO26N 做 Production；YOLOv8 与 RT-DETRv2/D-FINE 以低帧率 Shadow 或离线比较；YOLOE 用于预标候选；PatchCore/EfficientAD 在工件稳定后的 ROI 快照上触发。

## 14. 三路相机、Docker 网关与录像

### 14.1 单一采集所有权

当前 `/dev/video2` 和 `/dev/video4` 由旧版采集进程占用。8112 不停止旧站、不第二次打开设备，而是通过受控会话代理 8096 的三路 MJPEG。这样 8102、8111 和 8112 可同时使用同一采集结果，避免设备忙和随机黑屏。

### 14.2 网页实时画面

进入 02 页面后自动拉起主画面和三路相机墙。cam0 为 Insta360 Link 2C，cam1 为 icSpring WebCamera，cam2 为 Jieli USB Camera。实测分辨率分别为 960×540、160×120、960×540。第二路低分辨率来自当前上游设备模式，应在维护窗口调整驱动格式，页面不会伪报高清。

### 14.3 MediaMTX 容器

容器 `sop_camera_gateway_20260823` 使用 host 网络监听 RTSP 8554、HLS 8888、WebRTC 8889 和 API 9997。三个 host ffmpeg 发布器把受控 MJPEG 转为 H.264 Baseline、12 FPS 并发布到 cam0、cam1、cam2。MediaMTX 按 15 分钟 fMP4 分段录像，目录为 `2026.8.23/camera-recordings`，默认保留 7 天。

### 14.4 录像和存储

录像文件已实际生成，不是只创建空目录。运维每天检查 9997 路径 `ready`、容器状态、发布器服务、录像增长速度和磁盘水位。生产环境应把录像目录迁移到 NAS/MinIO，并根据法规、质量追溯和空间制定保留期。

#### 14.4.1 相机验收要点

三路都要检查非黑像素、分辨率、帧率、时间戳、RTSP 重连和录像可解码性。低分辨率设备必须显示真实值并进入整改清单，不能由 CSS 拉伸后当作高清验收。

## 15. 07 实时 SOP 与 MES 闭环

### 15.1 页面布局

左侧显示实时视频、ROI、目标框、Track、FPS 和延迟；右侧显示当前步骤、标准动作、持续时间、置信度、纠正方法、设备证据、状态机和 MES 事件。操作人员无需在多个页面间来回切换。

### 15.2 状态机判定

视觉证据与扫码枪、PLC、温度、扭矩、角度、打印机和 MES 指令按 SOP FSM 融合。顺序正确且所有门禁满足才 PASS；步骤错误、超时或关键对象缺失输出 NG/REWORK；证据或设备回执缺失输出 HOLD。视觉模型不能绕过确定性的扭矩、扫码或 MES 门禁。

### 15.3 MES 字段

回传至少包含 station_id、SN、recipe_version、step_id、result、event_time、model_version、dataset_version、evidence_uri、device_ack 和 audit_id。网络断开时本地排队，恢复后幂等补传；同一 audit_id 不得重复创建产品记录。

### 15.4 Hard Case

误报、漏报、低置信度、罕见 NG、设备掉线和 Reviewer 驳回进入 Hard Case。去重、绑定原视频和工位后分配下一轮标注，形成持续提高精度的闭环。

## 17. 备份、恢复与容量管理

### 17.1 必须备份的对象

备份配置模板、SQLite backup、Annotation Version、Dataset Manifest、Model Registry、训练日志、MES 审计和 MediaMTX 配置。原始视频和录像按 NAS/MinIO 策略备份。密钥文件单独加密保管。

### 17.2 SQLite 恢复

运行中使用 SQLite backup API，不直接复制主文件。恢复前停止目标新版本服务，保留原数据库副本，恢复后执行 `PRAGMA quick_check`，再核对标注数、保存轮次、CVAT 绑定和最新审计。不得用空库覆盖未知状态。

### 17.3 容量策略

原视频只存一次；annotation 和 manifest 长期保存；JPEG 帧缓存可重建并设置过期；全帧 ZIP 和带框 MP4 设置交付后清理；相机录像按 7 天或现场要求滚动；模型权重按 Registry 和回滚需要保留。

## 18. 安全、权限与合规

### 18.1 密钥和公开仓库

GitHub 只保存源码、配置示例、文档和不含隐私的 QA 报告。运行时、SQLite/WAL、账号、Token、Secret、相机密码、视频、录像和模型权重均由 `.gitignore` 和打包排除规则隔离。密码只在 SSH 或登录提示中输入，不写进命令、脚本或 README。

### 18.2 安全测试边界

渗透测试必须有书面授权、目标、时间窗、允许手段、数据范围和回滚责任。优先做依赖扫描、配置审计、认证授权、上传限制、API 越权、限流、日志和恢复演练。禁止向相机、SD 卡、第三方网络或未授权资产植入驻留和传播脚本。

### 18.3 Webhook 和内网

Webhook 端点必须 HMAC 验签、限制请求体、记录事件和失败原因。即使 CVAT worker 能访问内网，SOP 也不接受无签名请求。网络边界应进一步由防火墙限制到 CVAT 主机和端口。

## 19. 常见故障处理

### 19.1 页面或视频打不开

先确认客户端同网段，再检查 8112 服务和 `/api/health`。视频问题读取 `/api/videos/health`，看具体 `missing_media`，再检查媒体根目录和文件权限。浏览器必须收到 206 Range；只返回页面 200 不代表视频可播放。

### 19.2 导入后不进标注池

查看页面导入进度和 `/api/cloud/status` 的 job。检查源卷是否仍挂载、文件是否写完、复制大小、可解码性和云目录 manifest。完成后应自动刷新 `/api/videos` 并更新预标状态。

### 19.3 CVAT Failed to fetch

检查 8081 Host 路由、Token、Project 5、`lan-team` 组织、Task 绑定和浏览器网络。406 表示 Accept 类型不兼容，应使用 `application/vnd.cvat+json`。Webhook 看 CVAT deliveries 和 SOP sync jobs；202 只表示回调入队，仍要核对 annotation version 是否 completed。

### 19.4 无可构建数据集

确认版本是 Reviewer `accepted`。手工拉取的 `pending_review` 不能构建，这是门禁而非故障。检查标注数量、标签映射和 manifest 路径。

### 19.5 相机黑屏或被占用

先看 8096 上游和 MediaMTX 9997，确认三路 ready。不要直接杀死旧采集进程。若某路分辨率异常，在维护窗口检查 UVC pixel format、曝光、供电、数据线和稳定路径，再由唯一 Station Agent 重启设备。

### 19.6 导出很大

优先下载轻量 annotation-only ZIP。确实需要逐帧图片时降低最大宽度和 JPEG 质量，并在交付后清理。PNG 不适合作为长视频长期中间件。带框 MP4 通常远小于全帧 ZIP。

## 24. 结论

8112 已把参考图中的 01 至 07 业务流程落到同一站点，并修复媒体路径、导入刷新、CVAT vendor API、双向 Webhook、客户三种导出、YOLOv8 目录和三路共享相机。系统的核心原则是：原片只存一次、AI 先候选、人工可修改、Reviewer 才能冻结、模型同条件验收、现场证据与设备门禁共同决定、所有异常回到下一轮数据。
