# 公网 CVAT 保存导出与 SOP 视频回流整改

## 1. 架构

浏览器分别访问 SOP 公网入口和 CVAT 公网入口。两个 Cloudflare Tunnel 都是服务器主动建立的出站连接。CVAT Tunnel 进入同一 Traefik、`cvat_server` 和 PostgreSQL 数据卷；SOP 后端通过内网 API 访问同一 CVAT，并只在网页上公开 CVAT 公网地址。

数据链路如下：

1. 网盘视频断点下载到 `D:\NingboSOPData\Baidu_20260819_21`。
2. 下载完成一段，增量创建一个 CVAT Task，归入 Project #2。
3. SOP 视频目录登记同一原片的相对媒体路径，并记录 Task ID ↔ Video ID。
4. 标注员在公网 CVAT 保存框、Track 和属性。
5. SOP 调用 annotation-only 拉取，不重复导出整段 PNG。
6. SOP 使用同一原片播放标注结果，可生成坐标、帧 ZIP 或带框 MP4。

## 2. CSRF 修复

`deploy/cvat-cloudflare/production_cloudflare.py` 从环境变量读取精确受信任 Origin。由于当前 Quick Tunnel 进程使用 `--http-host-header 10.70.102.210` 适配 Traefik，本配置只在受信任 Origin 匹配时恢复公网 Host 与 HTTPS Scheme，使导出 `result_url` 返回公网地址。

部署前先备份数据库。将两个文件放入 CVAT 根目录后执行：

```powershell
wsl -d NingboSOP-CVAT -- bash -lc 'cd /mnt/d/NingboSOP_CVAT_20260824/cvat-v2.47.0/cvat-2.47.0 && docker compose -f docker-compose.yml -f docker-compose.cloudflare.yml up -d --no-deps cvat_server'
```

Quick Tunnel 域名变化时，必须同步修改 Compose 中的 `CVAT_CSRF_TRUSTED_ORIGINS` 与 `CVAT_BASE_URL`，再重建 `cvat_server`。不要重建 `cvat_db`，不要删除命名卷。

- 共享管理员：`cvat_admin`。
- 当前要求下密码由现场统一配置为 `123456`，源码和 GitHub 不保存密码。
- `cvat_admin` 为 active/staff/superuser。
- 两个 Project、九个 Task 均统一 owner 为 `cvat_admin`。
- Project #2 是网盘视频共享项目，SOP 的“打开 CVAT”和“共享项目”按钮都指向同一公网实例。

若后续需要人员级审计，应恢复 `labeler01`～`labeler05` 独立登录，并把他们加入同一个 Organization/Project；不要删除共享项目或重新导入视频。

## 4. 自定义标签

SOP 的“CVAT 自定义标签与数据字段”支持：

- 标签名称；
- 矩形、多边形、折线、关键点、整帧标签等形状；
- 标签颜色；
- 自定义文本字段；
- 自动业务字段：S01～S06、质量结论、物料编码。

后端调用 Project PATCH 写入标签。标签属于 Project，而不是某一个人的浏览器，因此所有使用同一 Project 的任务和人员看到同一目录。新增记录写入 SOP 审计 JSONL。

## 5. 端到端验收步骤

1. 用 `cvat_admin` 登录公网 CVAT，打开 Project #2。
2. 打开任意 Task/Job，修改或新增一个真实目标框，点击 Save。
3. 从 Actions 启动 `YOLO 1.1` 或 `CVAT for video 1.1` 导出。
4. 确认 Request 状态 finished，并从公网 HTTPS 地址下载 ZIP。
5. 登录新版 SOP，进入“04 CVAT人工复核”。
6. 在任务列表点击“选为同步任务”；对应整段视频自动切换。
7. 点击“从最近 CVAT 任务同步”，等待状态 completed。
8. 刷新标注版本，在视频上核对框、帧号和标签。

自动框仍是候选。没有人工标注的 Task 拉回 0 个框是正确结果，禁止为了演示伪造标注数量。
