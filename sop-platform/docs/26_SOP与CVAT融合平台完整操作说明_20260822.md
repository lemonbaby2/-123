## 1. 文档目的

本说明书用于指导现场人员完成“视频采集 → 数据清洗 → AI 预标 → CVAT 人工复核 → 数据集冻结 → 模型训练/验证 → 实时 SOP → MES 回传 → Hard Case 回流”的日常闭环。

2. 使用管理员线下发放的账号登录。首次账号保存在服务器权限为 600 的运行目录文件中，不应发送到公开群、GitHub 或部署包。

## 4. 总体闭环

原始视频只保存一份。SOP 平台维护 VideoAsset、来源、工位和 SHA256；CVAT 维护可编辑的 annotation；Dataset Builder 把已验收 annotation version、原 MP4 和 Frame Manifest 关联；训练产生可追踪 Model Version；现场误报、漏报、低置信度和 NG 稀有样本回到下一轮标注。

正式路径：

`采集 → QC/去重 → 工位标签模板 → AI 候选 → CVAT 修改 → Reviewer → Annotation Version → Dataset Version → Train/Val/Frozen Test → Model Registry → 实时 SOP → MES → Hard Case`

禁止路径：

- 未经 Reviewer 的 AI 候选直接进入正式训练。
- 把全部工位的总标签池直接套到每个任务。
- 把带框演示视频当作训练标签。
- 按相邻帧随机拆分 Train/Val/Test。
- 把视频、权重、Token、密码或数据库 WAL 上传公开仓库。

## 5. 01 总览

总览显示平台、DGX、CVAT、MES、视频任务、视觉证据、SOP 阶段、HOLD 状态和边缘设备。

HOLD 是默认安全状态。只有 SOP 顺序、视觉证据、设备回执、质量门禁和 MES ACK 同时满足时，才允许进入 PASS。页面上的候选数量或演示指标不能解除 HOLD。

## 6. 02 数据获取与清洗

1. 选择 RTSP/UVC 实时源、Google Drive、Pocket 3/SD 卡或本地历史视频。
2. 绑定工位、产品/SN、采集日期和来源。
3. 使用 ffprobe 检查时长、FPS、分辨率、编码和可解码性。
4. 使用来源文件 ID 和 SHA256 去重；损坏、零长度、未写完和重复视频进入隔离区。
5. 对浏览器不兼容或超大视频生成 H.264 代理，原片保留，不覆盖。
6. 记录 ROI、抽帧策略、VideoAsset 和审计时间。

页面“采集来源与只读介质导入”会显示当前 UVC/RTSP 数量、Pocket 3/SD 卷和 Google Drive 17:00 状态。介质视频默认只勾选前三段，确认容量和文件名后再点击“导入选中视频”。复制过程使用 `.part`、SHA256 和原子改名，不修改来源介质。

## 7. Pocket 3、SD 卡与相机设备

当前检测到的 Pocket 3 是 USB 存储模式：卷标 `DJI_POCKET3`、exFAT、UUID `2A1B-D624`。这种模式下没有 `/dev/video*`，因此只能作为只读历史视频来源，不能实时推流。

若要实时检测：

1. 使用原厂支持的 UVC/Webcam 模式和数据线。
2. 在 Linux 上确认出现 `/dev/video*` 和 `/dev/v4l/by-id/*`。
3. 在 02 页面重新盘点设备。
4. 在 07 页面启动实时源，检查分辨率、FPS、延迟和重连。

平台按 VID/PID、序列号、稳定设备路径和存储卷 UUID 识别设备。不会向 Pocket 3、相机固件或 SD 卡刷入渗透、驻留、传播或“记住局域网”的脚本。此类脚本会破坏设备可信边界并形成未授权持久化。合法做法是主机侧 udev/设备登记、只读导入和受控网络相机配置。

当前登记的 UVC 身份包括 Insta360 Link 2C、Jieli USB Composite Device 和 icSpring WebCamera。量产相机需额外完成 8 小时稳定性、断线重连、时间同步和现场照明测试。

## 8. Google Drive 每日 17:00

交付包含 `daily_drive_ingest.py`、systemd service 和 timer 模板。策略是 17:00 只抓取、校验、入库和进入预标队列；Reviewer 验收前绝不自动正式训练。

首次配置：

1. 由管理员执行 `rclone config`，使用 Google OAuth 授权，不输入或保存 Google 账号密码到脚本。
2. 把目标文件夹配置为受控 remote，并设置 `SOP_GOOGLE_SOURCE`。
3. 在 `/etc/ningbo-sop/drive-ingest.env` 保存运行参数，权限设为仅服务用户可读。
4. 手工运行一次 service，核对新增文件、ffprobe、SHA256、重复项和失败日志。
5. 验证无误后再启用 timer。

当前本机 `rclone listremotes` 没有可用 remote，因此 timer 不应在生产启用。页面“待 rclone OAuth”是正确状态。

## 9. 03 AI 预标注与现场证据

1. 先选择工位专用标签模板。例如 PCB 固定工位只使用 PCB、夹具、插件、手部、工具和该工位步骤标签。
2. 人工标注同一工位前几次完整 SOP 循环，优先覆盖正常、遮挡、转向、速度变化和步骤边界。
3. 选择预标模型、抽帧范围和阈值。
4. 固定目标使用检测/分割候选，移动目标使用 Tracking/SAM2 类候选。
5. 检查候选数量、类别分布、越界框、误框和漏框。
6. 将结果标为“待人工复核”，不能直接进入正式训练。

现场证据页会显示当前步骤、风险分、必需项完备度、ROI、动态目标、小目标候选、缺失证据和处置建议。点击“误报”“需要返工”或“人工确认”会留审计记录，但不会自动把 AI 候选升级为生产真值。

## 10. 04 CVAT 人工复核与双向同步

AI 自动标注进入 CVAT 后可以继续删除、移动、缩放、改类别、补框、调整关键帧和修 Track，不需要退回纯人工从零标注。

推荐操作：

1. 在 SOP 平台确认当前视频和固定工位标注口径。
2. 点击“创建并上传整段视频”建立绑定的 CVAT Task。
3. 点击“SOP → CVAT”同步当前候选。该操作可能替换对应 Task 标注，执行前确认 Task ID。
4. 在 CVAT Job 中播放视频，逐段检查框和 Track。
5. 遮挡、转向、速度突变和步骤边界增加关键帧。
6. 跟踪漂移时分段修正；同一物体保持 Track ID 连续。
7. 标注员保存并提交 Reviewer。
8. Reviewer 检查漏标、误标、类别混淆、NG 稀有样本和步骤边界。
9. 不通过则驳回；通过后记录审核人、时间和 annotation version。
10. 点击“从最近 CVAT 任务同步”，平台只拉 annotation JSON 和 Frame Manifest。

手工拉取只能生成 `pending_review`，不能伪造 `accepted`。正式 `accepted` 只能来自受 HMAC-SHA256 验签的 CVAT acceptance/completed Webhook。

## 11. SOP 网页标注与自动恢复

网页标注支持播放/暂停、上一帧、下一帧、跳帧、时间轴、画框、移动缩放、关键帧、插值、自动跟踪、删除单框、删除整轨和删除轨迹区间。

1. 选择视频、数据来源和审核状态。
2. 跳到起始帧，拖动鼠标画框。
3. 选择工位区域、细分类标签和 Track ID。
4. 设置起始关键帧，跳到后续帧，必要时校正结束框。
5. 执行自动跟踪，逐段复核中间框。
6. 点击“保存这个框”，一批完成后点击“保存本次进度”。

数据写入 SQLite WAL，页面保存恢复点和审计记录。浏览器刷新或异常退出后，先点击“恢复自动缓存”，核对视频、帧号、草稿框和数据库轮次。服务运行时不能只复制 SQLite 主文件而遗漏 WAL，应使用平台备份或 SQLite backup API。

## 12. 2.96 MB 视频为什么导出约 2 GB

MP4 使用帧间压缩，大量相邻画面只保存变化。导出 630 张独立 PNG/JPEG 后，每帧必须保存完整画面，压缩优势消失。约 2 GB / 630 帧约为 3.25 MB/帧，这与独立高分辨率图片的体积相符，不是原视频被简单复制了 600 多次。

正确策略：

- 原 MP4 只存一次。
- annotation XML/JSON 单独版本化。
- Frame Manifest 记录 frame index、时间戳和原视频关系。
- 05 阶段按训练需要生成 JPEG 缓存，设置尺寸、质量、水位和过期时间。
- 带框视频只用于审阅展示，不作为训练标签。
- 不把全量 PNG 作为长期中间件或跨系统同步单位。

## 13. 05 数据集构建与质量冻结

1. 在“已验收 Annotation Version”选择 Reviewer 已通过的版本。
2. 输入工位 ID 和产品族。
3. 点击“冻结数据集”。
4. 平台生成 Dataset ID 和 `dataset_manifest.json`，关联 annotation SHA256、原视频、工位、产品族和拆分规则。
5. 运行类别分布、空标签、越界框、重复帧、路径完整性和许可证检查。
6. 按完整视频、产品 SN、工位或日期划分 Train/Val/Test，冻结测试集。

Dataset Builder 会拒绝 `pending_review`。冻结过程不会生成全量 PNG。训练缓存可重建，不进入 Git。

## 14. 06 五模型训练、验证与部署

- YOLO26N：生产实时基线，当前训练执行器可用。
- YOLOE-26S + SAHI：开放词汇和小目标候选生成，候选流程可用。
- RT-DETRv2：Shadow 或离线交叉验证，训练后端待安装。
- D-FINE：边界定位候选，训练后端待安装。
- PatchCore/EfficientAD：划痕、污迹、涂料不均匀等事件触发异常检测，训练后端待安装。

正式训练步骤：

1. 选择已冻结 Dataset Version 和模型。
2. 真值模式选择“仅人工确认真值”。
3. 设置 epochs、batch、输入尺寸、GPU、随机种子和输出目录。
4. 启动训练并保存日志、代码提交、环境、数据集版本和基础权重哈希。
5. 在固定测试集输出 Precision、Recall、mAP50、mAP50-95、NG Recall、P95 延迟和稳定性。
6. 通过验收后进入 Model Registry，先灰度单工位，并保留旧版本和回滚入口。

不要让五个模型都以 30 FPS 同时参与生产判定。建议 YOLO26N 为 Production，RT-DETRv2/D-FINE 以 1～5 FPS 做 Shadow/离线验证，PatchCore/EfficientAD 在工件稳定后的 ROI 快照上事件触发。

## 15. 07 实时 SOP 与 MES

页面左侧用于 RTSP/UVC 实时视频、ROI、检测框和 Track；右侧用于 SOP 步骤、标准动作、持续时间、置信度、纠正方法和最终状态。

1. 选择工位、Recipe、Model Version 和摄像头。
2. 点击“启动实时源”，确认不是黑帧，检查 FPS、延迟和重连。
3. 核对右侧当前步骤和标准动作。
4. 把视觉证据与扫码枪、PLC、温度、扭矩/角度、打印机和 MES 指令按 SOP FSM 融合。
5. 顺序正确且全部门禁满足才输出 PASS。
6. 步骤错误、超时或关键目标缺失输出 NG/REWORK。
7. 证据或设备回执缺失输出 HOLD。

MES 回传至少包含工位、SN、Recipe、步骤、结果、时间、模型版本、证据 URI 和审计 ID。误报、漏报、低置信度和 NG 稀有样本进入 Hard Case 待审队列。

## 16. CVAT 本地系统使用

打开 8081 后常用入口包括 Projects、Tasks、Jobs、Cloud Storages、Models、Webhooks、Organization 和 API。

标注员日常路径：

1. 打开绑定 Task 和分配的 Job。
2. 使用矩形、Polygon、Mask、Skeleton 或 Track 工具。
3. 用播放、逐帧和关键帧检查完整视频。
4. 选中对象后修改标签、属性和位置；删除错误对象或错误轨迹。
5. 在遮挡、出画、重现和步骤边界设置关键帧。
6. 保存并提交审核。

Reviewer 日常路径：

1. 检查标签映射是否属于该固定工位。
2. 抽查完整循环，而不是只看少量漂亮画面。
3. 检查漏标、误标、框偏移、Track 漂移和 NG 样本。
4. 不合格则退回并写明原因；合格后进入 acceptance/completed 状态。
5. 由 Webhook 触发 annotation-only 回拉。

CVAT 2.73.1 当前原生作业页仍以官方界面为准，融合平台提供中文业务入口和流程说明。修改 CVAT 源码汉化会增加升级维护成本，应优先采用官方可升级版本和平台侧中文封装。

## 17. 数据、备份和容量规范

- 原始视频只存一次，优先放 MinIO/NAS 或受控数据卷。
- Annotation Version、Frame Manifest、Dataset Version 和 Model Version 独立版本化。
- JPEG 缓存设置水位和生命周期；可重建缓存不进入 Git。
- 视频、权重、数据库、WAL、账号、Token、Webhook Secret 和相机凭据不进入公开仓库。
- 删除操作保留审计事件，不静默抹除历史版本。
- 数据库备份使用 SQLite backup API 或停服后同时处理主文件、WAL 和 SHM。
- 每次部署前执行恢复演练，不只检查“备份文件存在”。

## 18. 局域网、公网与安全

异地访问应采用企业 VPN 或固定域名的受控反向代理，并配置 TLS、MFA/强认证、角色权限、限流、日志、备份和告警。临时隧道只能调试，不能作为生产入口。

安全测试必须先取得书面授权，明确目标、时间窗、允许手段、数据范围和回滚责任。优先执行依赖漏洞扫描、配置审计、认证授权、上传限制、API 越权、速率限制、备份恢复和日志检查。不得向相机、SD 卡、第三方网络或未授权资产植入渗透、驻留或传播脚本。

8. 检查数据库、配置、标注版本和模型注册表备份。

## 20. 故障处理

- 页面打不开：确认客户端和 192.168.1.129 同网段，检查 8111 监听和主机防火墙。
- CVAT 打不开：使用 `http://192.168.1.129:8081/tasks`，检查 Docker 和 Traefik Host 路由。
- Pocket 3 没实时画面：确认是否为存储模式；只有出现 `/dev/video*` 才是 UVC 实时源。
- Google 抓取失败：检查 rclone remote、OAuth、文件夹权限、网络和 service 日志。
- 无可构建数据集：确认 annotation version 已由 Reviewer acceptance/completed Webhook 标为 accepted。
- 导出体积过大：使用 annotation-only，不导出全量 PNG。
- 页面刷新丢草稿：使用“恢复自动缓存”，核对保存轮次和 SQLite WAL。
- 摄像头黑帧：停止后重新盘点，检查设备占用、UVC 格式、供电、数据线和曝光。
- 融合站摄像头提示被占用：旧站采集进程仍在保护性运行时，不强行停止旧站。应由唯一 Station Agent 打开 UVC，并向 8102/8111 分发 RTSP/MJPEG；或在批准的切换窗口迁移设备所有权。

## 21. 验收标准

交付验收必须附人工审核人、冻结数据集版本、拆分规则、模型哈希、阈值、测试报告、P95 延迟、8 小时稳定性、断网补传、设备掉线、模型回滚、MES ACK 和备份恢复记录。

自动候选数量、带框演示视频、网页中的模型名称和未冻结数据上的高指标不能替代验收证据。未完成人工真值、同条件对比和现场联调时，量产状态保持 HOLD。
