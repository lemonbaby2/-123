# 宁波视觉 SOP 与 CVAT 标注、训练、推理会议操作手册

版本：V1.0（2026-08-24 培训版）  
适用平台：SOP 分布式预标注与温控版 `http://192.168.1.129:8116`  
CVAT：`http://192.168.1.129:8081`  
适用人员：视频采集员、标注员、Reviewer、算法/训练管理员、现场班组长和 MES 联调人员

> 本文档不记录账号密码、恢复码、Token、摄像头凭据和生产数据。账号由管理员线下按岗位发放。培训使用独立演示任务，严禁在生产任务中试按 Delete、改标签或切换审核状态。

## 1. 培训目标与职责边界

### 1.1 培训完成后每个人应会什么

培训完成后，标注员应能独立登录 SOP 与 CVAT，识别 02 至 07 的业务顺序，选择正确工位和视频，检查 AI 候选框，在 CVAT 中创建矩形框、单击选框、移动和缩放框、修改标签、用 Delete 删除误框、创建 Track、补关键帧、保存并提交复核。Reviewer 应能检查漏标、误标、类别混淆、轨迹漂移和步骤边界，决定通过或驳回。训练管理员应能把通过审核的 annotation-only 版本同步回 SOP，冻结 Dataset Version，在温控和资源互斥条件满足时启动训练与验证，并在 07 页面验证实时 SOP 与 MES 闭环。

### 1.2 五类岗位职责

1. 采集员负责相机、SD 卡、本地 MP4、Google Drive 增量视频的来源登记、工位绑定和完整性检查，不负责修改标注真值。
2. 标注员负责 AI 候选的人工核对、删除、补框、改类别和 Track 修正。标注员不得把“看起来差不多”的候选直接全部通过。
3. Reviewer 负责第二人复核，重点检查漏标、稀有 NG、步骤边界和连续轨迹。Reviewer 不应审核自己刚完成的正式生产任务。
4. 训练管理员负责数据冻结、训练参数、GPU 温度、固定测试集、模型注册和回滚。没有 Reviewer 通过版本时不得启动正式训练。
5. 班组长/MES 管理员负责 07 页面现场结果、设备回执、PASS/NG/REWORK/HOLD、证据 URI 和 Hard Case 闭环。

### 1.3 培训必须记住的四条规则

- AI 预标只是 `pending_review` 候选，不是人工真值。
- 本轮使用工位级标签，不给电阻、电容、电感、芯片等微小元器件逐个打框。
- 原始 MP4 只保存一次；标注回流优先使用 annotation-only 和 Frame Manifest，不长期保存全量 PNG。
- 训练与批量预标互斥，温控优先；固定测试集验收完成前，量产状态保持 `HOLD`。

## 2. 系统地址、登录与会前检查

### 2.1 访问地址

SOP 培训和当前开发版本使用 `http://192.168.1.129:8116`。官方 CVAT 使用 `http://192.168.1.129:8081`。这两个地址是厂内局域网地址，浏览器必须连接到同一局域网或经过公司批准的 VPN。浏览器代理 `all_proxy=http://127.0.0.1:7890` 不应代理 `192.168.0.0/16`；如网页偶尔无法打开，应将 `192.168.1.129` 加入 `NO_PROXY/no_proxy`，不要反复重启容器。

历史端口 8102、8113、8114、8115 是冻结版本，不用于本次培训修改。访问历史站点时仍使用各自原账号库，不与 8116 共享登录状态。

### 2.2 SOP 登录

打开 8116 后，输入管理员线下发放的岗位账号和密码。开发者、管理者和普通员工的可见菜单不同。普通标注员看不到训练和系统管理能力是正常权限控制，不是功能丢失。首次登录后不要在工位显示器旁张贴密码；需要修改时使用右上角“修改密码”。忘记密码时由管理员线下提供恢复码，恢复码不得发到群聊或写进本手册。

![图1 SOP登录页](../01_截图/01_SOP登录页_未填写凭据.png)

操作位置：右侧登录工作台。操作目的：建立可审计的岗位身份。成功判据：登录后右上角显示本人名称和岗位，左侧菜单与岗位权限一致。失败时先确认地址是 8116、大小写和输入法，再联系管理员，不要连续猜测密码。

### 2.3 CVAT 登录

打开 8081 后，先输入用户名并点击 `Sign in`，再在第二步输入密码并点击“下一步”。CVAT 与 SOP 是两个独立账号系统，SOP 登录成功不代表 CVAT 自动登录成功。浏览器可以同时保持两个标签页，但不要把生产管理员账号长期留在公共工位。

![图2 CVAT第一步登录](../01_截图/09_CVAT登录页_未填写凭据.png)

![图3 CVAT第二步登录](../01_截图/10_CVAT密码步骤_未填写凭据.png)

成功判据：进入 CVAT 任务列表，右上角显示本人账号；失败时确认没有误用 SOP 密码。培训过程中不得把输入完成后的密码页面截图、录屏或发群。

### 2.4 会前五分钟健康检查

1. 用浏览器分别打开 8116 与 8081，确认 HTTP 页面能加载。
2. 在 8116 总览确认平台在线、CVAT 可达、当前产线正确。
3. 在 02 页面确认演示视频有缩略图、时长、FPS 和分辨率。
4. 在 CVAT 任务列表确认“验收测试”或“培训演示”任务可打开。
5. 训练管理员检查 GPU 温度和是否存在预标任务。温度过高或预标运行时，不启动训练。
6. 关闭会弹出通知、聊天消息或密码管理器的窗口，防止录屏泄露。

## 3. 全链路逻辑流程

![图4 SOP、CVAT、训练、推理和MES闭环流程图](../02_流程图/宁波视觉SOP_CVAT训练推理MES闭环流程图.png)

### 3.1 数据对象之间是什么关系

`VideoAsset` 是原视频资产记录，保存视频 ID、工位、来源、时长、FPS、分辨率、SHA256 和代理视频地址。原片只保存一次，浏览器播放不兼容或文件过大时生成 H.264 代理，但不覆盖原片。

`AI Candidate` 是模型生成的候选框，状态为 `pending_review`。候选框用于加速人工工作，不直接进入正式训练。人工确认、修改或删除后才形成可审核标注。

`Annotation Version` 是一次可追溯的标注版本，包含任务、视频、标签映射、框/轨迹、审核状态、时间和哈希。CVAT 回流时只拉取标注 JSON/XML 和 Frame Manifest，不需要把每帧 PNG 当成长期中间件。

`Dataset Version` 是经过 Reviewer 门禁、质量检查和 Train/Val/Test 隔离后的冻结数据集。模型训练必须引用明确的数据集版本，不能引用“当前目录里有什么就训练什么”。

`Model Version` 保存权重、代码提交、环境、基础权重哈希、阈值和固定测试集报告。模型名称出现在页面上不等于已经训练成功；只有真实权重和验收报告都存在才可注册。

### 3.2 为什么 2.96 MB 视频会导出约 2 GB

MP4 使用帧间压缩，相邻画面只记录变化；逐帧导出 PNG 后，每张图片都独立保存完整像素，因此容量会大幅膨胀。630 帧压缩包约 2 GB，相当于平均每帧约 3.25 MB，这与逐帧高分辨率 PNG 的体积一致。正确做法是保留一份原始 MP4，把标注坐标按帧号单独保存；训练阶段再按需抽取 JPEG 缓存，并设置质量、尺寸和过期策略。

带框 MP4 用于复核和演示，不是训练标签。逐帧带框 JPEG 压缩包只在客户明确需要逐帧材料时导出；默认训练交付选择 annotation-only，可显著降低传输和存储压力。

## 4. 02 数据获取与清洗

### 4.1 选择数据源

进入左侧“02 数据获取与清洗”。数据源可以是 RTSP/UVC 实时相机、Pocket 3/SD 卡、本地历史 MP4 或经过 OAuth/rclone 授权的 Google Drive 增量目录。先选择正确工位、产品/SN、拍摄日期和来源，再执行导入。不要把不同工位的视频混在一个无工位标识的目录中。

![图5 数据获取与清洗](../01_截图/讲解标注/03_02数据获取与清洗.png)

### 4.2 导入后的六项检查

1. `ffprobe` 可读取时长、FPS、分辨率和编码，没有截断或损坏。
2. SHA256 或 Drive file_id 没有与已有资产重复。
3. 工位、产品/SN 和拍摄日期正确，不能用文件名猜工位后直接训练。
4. 浏览器不兼容时生成 H.264 代理，原片仍保留。
5. ROI 和抽帧策略与工位对应，不将其他产线模板直接套用。
6. 缩略图和视频框能播放，时间轴可以跳转，画面方向正确。

成功判据：视频进入 VideoAsset 列表，有唯一 ID、来源和校验状态，并能在浏览器加载。失败视频进入隔离区，不应继续预标。

## 5. 03 AI 预标注与现场证据

### 5.1 选择工位专用标签模板

进入“03 AI预标注与现场证据”。先确认当前产线和工位，再选模型、视频和抽帧/全帧范围。PCB、汽车固定件、模塑/涂装使用各自标签模板，不能把总标签池无条件套到所有工位。本轮目标是工位级对象和操作行为，例如 PCB、工件、手部、工具、料盒、关键装配区域；电阻、电容、电感和芯片等板内微小元器件暂不逐个打框。

![图6 AI预标注](../01_截图/讲解标注/04_03_AI预标注与现场证据.png)

### 5.2 启动与检查预标

点击启动前确认 GPU 没有进行正式训练。任务启动后观察已处理帧数、总帧数、候选数、失败重试、worker 状态和 GPU 温度。当前单机只有一块 GPU，因此分布式协调器用于拆分任务、租约、暂停恢复和未来多节点扩展，不应描述成已经完成多机多卡训练。

候选生成后抽查开头、中间、结尾和步骤边界。错误类型包括：框太大覆盖多个对象、同一对象重复框、标签错、漏掉关键工具、手部遮挡后轨迹漂移、跨步骤继续沿用旧 Track。明显异常时先暂停任务并核对工位模板，不要让错误候选继续扩散。

成功判据：预标状态完成、候选属于当前工位标签、排除的微小元件没有被打框、候选状态仍为 `pending_review`。页面上的候选数量不能作为精度验收证据。

## 6. 04 SOP 初审与 CVAT 双向同步

### 6.1 SOP 页面先做什么

进入“04 CVAT人工复核”。选择视频后，先在 SOP 页面浏览 AI 候选，快速删除明显误框、补充遗漏区域、核对标签和时间范围。单击框后会进入选中状态；工具栏删除或键盘 Delete 可删除当前选中对象。Track 起止范围应围绕目标真实可见区间，不要为了省事把一条漂移轨迹保留到整段视频末尾。

![图7 SOP与CVAT双向同步](../01_截图/讲解标注/05_04_SOP人工复核与CVAT双向同步.png)

### 6.2 SOP → CVAT

选择“创建并上传整段视频”时，系统把浏览器可播放代理视频、工位标签映射和已保存候选绑定到 CVAT Task。已有绑定任务时优先“打开完整 CVAT Job 工具台”，避免为同一视频重复创建多个任务。任务名称应包含工位、日期、视频或 SN 和用途，例如“NB-IP-SOP-01_20260824_培训复核”，不要只写“测试”。

成功判据：下方任务记录出现 CVAT Task ID 和绑定视频；点击打开后进入官方 CVAT 作业。CVAT 官方禁止 iframe 嵌入，因此新标签页打开是正确设计，不是桥接失败。

### 6.3 CVAT → SOP

CVAT Reviewer 通过后，回到 SOP 的 04 页面选择对应任务，点击“从最近 CVAT 任务同步”。系统应生成 Annotation Version、Frame Manifest、审核状态和哈希。同步的是 annotation-only，不是另一份带框视频。原 MP4 通过 video_id 与帧号重新关联，因此标注数据可以和原视频准确结合。

成功判据：标注版本列表出现新的版本 ID、CVAT Task ID、视频 ID、审核状态和时间；重复触发相同版本不会产生内容不同的重复数据。Webhook 自动同步失败时可人工点击同步，但必须核对任务与视频绑定。

## 7. CVAT 工人标注操作

### 7.1 打开正确任务和 Job

CVAT 登录后在任务列表搜索任务名称或 ID，确认缩略图、视频名称、帧数和工位，再点击打开。一个 Task 可能拆成多个 Job，标注员只处理分配给自己的帧段。进入 Job 后，中间是视频画布，左侧是绘制工具，顶部是播放、逐帧、保存、撤销和重做，右侧是对象列表、标签和外观，底部是时间轴。

![图8 CVAT任务列表](../01_截图/讲解标注/11_CVAT任务列表.png)

![图9 CVAT完整工作台](../01_截图/讲解标注/12_CVAT完整标注工作台.png)

### 7.2 创建一个矩形 Shape

1. 将时间轴停在目标清晰的一帧，必要时用逐帧按钮前后检查。
2. 点击左侧矩形工具，确认弹出的标题是“绘制新矩形框”。
3. 选择正确标签；标签来自工位模板，禁止临时用相近总类代替。
4. “绘制方式”通常选择“两点对角绘制”。极端遮挡或几何要求明确时才使用四个极值点。
5. 选择“形状”，鼠标从目标左上角拖到右下角，框应贴合工位级目标边界。
6. 画完后检查右侧对象列表出现新对象，标签和帧号正确。

![图10 Shape与Track选择](../01_截图/讲解标注/13_CVAT矩形框_形状与Track选择.png)

![图11 新建并选中矩形框](../01_截图/讲解标注/14_CVAT新建并选中矩形框.png)

框不应切掉目标主体，也不应包含大片无关背景。相邻目标必须分开标，除非工位标签定义本身就是整体区域。目标暂时被手遮住时，不要凭空画一个猜测位置。

### 7.3 选中、移动、缩放和改标签

在画布上单击框，或在右侧对象列表单击对应行。选中后可拖动框体移动，拖动控制点缩放。改标签时从对象属性选择工位模板中的正确标签。任何移动、缩放或改标签后都要查看当前帧和前后帧，避免修正一帧却破坏 Track 的连续性。

如果鼠标点击框感觉卡，优先确认只显示当前帧附近对象、关闭不必要轮廓和投影、缩小对象列表过滤范围，并使用平台已有命中缓存。不要同时打开多个高分辨率视频标签页；浏览器缩放建议保持 100%。

### 7.4 用 Delete 删除误框

先单击目标框或对象列表，确认只有要删除的对象高亮，再按键盘 `Delete`。也可以使用对象操作菜单中的删除。删除后对象应立即从画布和右侧列表消失。若系统询问删除单帧、整轨或轨迹区间，必须按实际意图选择：误画的独立 Shape 删除单框；整条错误 Track 删除整轨；仅局部漂移时删除或修正对应区间。

![图12 Delete删除结果](../01_截图/讲解标注/15_CVAT_Delete删除演示框.png)

Delete 是高风险快捷键。生产任务中删除后先用撤销检查，再保存；不要边播放边连续按 Delete。培训演示使用独立任务，演示草稿不保存。

### 7.5 创建 Track、设置起始帧和结束帧

1. 把时间轴停在目标第一次清晰出现的帧，这一帧就是 Track 起始帧。
2. 点击矩形工具，选择正确标签，再选择“跟踪轨迹”。
3. 画出起始框，向后播放或跳帧检查插值。
4. 遮挡、转向、速度突变、相机晃动和 SOP 步骤边界处添加关键帧并修框。
5. 到目标最后可见帧后，下一帧把对象设置为 Outside，或按任务规则结束/分割 Track。这才是有效结束帧，不要仅在备注里写结束时间。
6. 跟踪漂移时在漂移开始前后增加关键帧；无法可靠连接时分成两条 Track，不保留错误传播。
7. 同一个实际物体在连续可见期间保持同一 Track ID；两个不同物体不能合并为一条 Track。

![图13 Track与关键帧](../01_截图/讲解标注/16_CVAT_Track与关键帧演示.png)

成功判据：右侧对象列表显示 Track，时间轴上可看到关键帧；逐帧播放时框跟随目标，起止位置和可见状态正确。

### 7.6 保存与提交 Reviewer

每完成一个短片段就点击顶部“保存”，不要等整段做完才保存。保存后确认没有红色错误提示。标注员完成分配帧段后，把 Job 状态提交到 Reviewer 流程；不能仅口头说“做完了”。Reviewer 检查通过后更新审核状态，不通过时写明帧号、对象 ID、错误类型和修正要求再驳回。

Reviewer 抽查至少覆盖：视频开头和结尾、每个 SOP 步骤边界、遮挡和转向、稀有 NG、低置信度候选、目标进入和离开、标签容易混淆的帧。审核通过不代表模型可以直接量产，后面还需要数据冻结和固定测试集验收。

## 8. 05 数据集构建与质量冻结

### 8.1 选择验收版本

回到 SOP 的“05 数据集构建”，在“已验收 Annotation Version”中选择 Reviewer 通过的版本，核对工位 ID、产品族、视频 ID、标注数、标签映射和哈希。未通过审核或只有 AI 候选的版本不能冻结为正式训练集。

![图14 数据集构建](../01_截图/讲解标注/06_05数据集构建与质量冻结.png)

### 8.2 Train、Val、Test 拆分

按完整视频、产品 SN、工位或日期拆分，禁止把同一视频相邻帧随机分到训练集和测试集。相邻帧高度相似，随机拆分会造成数据泄漏，指标虚高但现场效果差。固定测试集一旦确定不得随着每轮训练随意更换；新增 Hard Case 可以进入下一版本，但要保留原固定测试集用于纵向比较。

质量检查包括空标签、越界框、零面积框、重复帧、路径缺失、标签映射不一致、类别分布失衡、Train/Val/Test 源视频重叠和 Reviewer 状态。全部通过后点击冻结，生成 Dataset Version 和 SHA256。

### 8.3 三种导出供客户选择

- annotation-only：推荐用于 SOP 回流和训练，体积最小，包含框、Track、标签、帧号和 Manifest。
- 标注成片 MP4：推荐用于会议复核和客户演示，视频上烧录框与标签，但不能替代训练真值。
- 全帧带框 JPEG 压缩包：仅在客户明确要求逐帧图片时使用，容量最大，生成时间也最长。

默认不导出全量 PNG。需要图片训练时，在 05 阶段按需生成 JPEG 缓存，训练完成后按生命周期清理可重建缓存。

## 9. 06 训练、验证与部署

### 9.1 启动前门禁

进入“06 训练与部署”，从下拉列表选择已标注并冻结的视频/数据集。页面显示第 0 帧缩略图、Reviewer 状态、标注数和 Dataset Version，用于防止选错数据。启动前必须满足：Reviewer 已通过、Dataset Version 已冻结、预标任务已暂停、GPU 温度低于门槛、没有其他训练任务、磁盘容量充足、固定测试集可用。

![图15 训练、验证与部署](../01_截图/讲解标注/07_06训练验证与部署.png)

### 9.2 模型分工

YOLO26N 是实时生产基线。YOLOE-26S + SAHI 用于开放词汇和候选生成。YOLOv8s-World v2 是 Ultralytics 兼容基线。RT-DETRv2 和 D-FINE 适合作为 Shadow 或离线交叉验证，但当前完整训练后端未安装时必须显示“待安装”。PatchCore/EfficientAD 用于工件稳定后的 ROI 异常检测；未安装完整后端时不能把页面卡片当成训练成果。

不建议五个模型都以 30 FPS 同时参与生产判定。生产模型负责实时主判，Shadow 模型按较低 FPS 做交叉验证，异常模型在事件触发快照上运行，以降低服务器温度和延迟。

### 9.3 温控和资源策略

当前主机只有一块 NVIDIA GPU。预标 worker 采用小 batch、较低 imgsz、低进程优先级和温度门禁；达到 70°C 暂停，降到 62°C 再恢复。正式训练前暂停预标，训练和预标不抢同一块 GPU。页面中的多卡 DDP 只有检测到真实多 GPU 节点后才可启用，不能把任务切片协调器说成多卡训练已完成。

训练保存 epochs、batch、输入尺寸、设备、随机种子、代码提交、环境、数据集版本和基础权重哈希。发生过热、CUDA OOM、磁盘不足或数据缺失时任务应失败或暂停，不允许用模拟成功状态掩盖。

### 9.4 验证和模型注册

固定测试集输出 Precision、Recall、mAP50、mAP50-95、NG Recall、P95 延迟和稳定性。工业现场优先关注关键 NG Recall、误放行风险和 P95 延迟，而不是只看 mAP50。通过阈值后模型进入 Model Registry，先灰度一个工位，保留旧版本和回滚入口。没有 8 小时稳定性、断网补传、设备掉线、模型回滚和 MES ACK 记录时，量产状态保持 HOLD。

### 10.1 页面布局

进入“07 实时SOP + MES”。左侧显示 RTSP/UVC 实时画面、ROI、检测框、Track、FPS 和延迟；右侧显示当前步骤、标准动作、持续时间、置信度、纠正方法及 PASS/NG/REWORK/HOLD。现场演示前选择正确工位、Recipe、模型版本和相机，不要用预录视频冒充实时摄像头。

![图16 实时SOP与MES](../01_截图/讲解标注/08_07实时SOP与MES.png)

### 10.2 判定逻辑

视觉证据与扫码枪、PLC、温度、扭矩/角度、打印机和 MES 指令按 SOP FSM 融合。顺序正确且全部门禁满足才输出 PASS；步骤错误、超时或关键目标缺失输出 NG 或 REWORK；证据缺失、相机掉线、设备无回执或模型未验收输出 HOLD。HOLD 不是失败，而是阻止系统在证据不足时错误放行。

MES 回传至少包含工位、SN、Recipe、步骤、结果、时间、模型版本、证据 URI 和审计 ID。断网时进入本地队列，恢复后按审计 ID 幂等补传。误报、漏报、低置信度和稀有 NG 自动进入 Hard Case 待审队列，去重并经人工确认后回到下一轮 03/04。

## 13. 常见问题与处理

### 13.1 视频加载不出来

先确认页面能访问，再检查视频是否有 H.264 代理、浏览器是否支持编码、文件路径是否存在、Range 请求是否成功。刷新前记录视频 ID 和当前帧。不要通过覆盖原片或反复上传同一文件来“试试看”。相机黑屏时检查 RTSP/UVC 源、MediaMTX、摄像头占用和网络延迟；页面控件正常但画面黑，不代表检测模型已失败。

### 13.2 单击框很卡

关闭多余标签页，浏览器缩放恢复 100%，对象列表按标签或当前帧过滤，关闭不必要的投影/轮廓显示。优先使用当前版本的框命中缓存。若画布不卡但保存慢，检查数据库、WAL 和备份；若画布本身掉帧，检查代理视频分辨率和浏览器 GPU 加速。

### 13.3 Delete 没有反应或误删

确认焦点在画布且目标已高亮，输入框中按 Delete 只会删除文字。误删后立即用撤销，不要先保存。Track 删除时看清是单帧、区间还是整轨。保存后发现误删则按审计记录和 Annotation Version 回退，不能直接修改数据库。

### 13.4 CVAT 保存后 SOP 看不到新版本

确认 Task 与 VideoAsset 绑定、Reviewer 状态、CVAT Token、Webhook 和网络。先在 SOP 04 点击人工同步，查看同步任务状态；不要手动下载 2 GB ZIP 再塞回系统。相同 annotation 版本重复同步应保持幂等。

### 13.5 无法冻结数据集

检查 Annotation Version 是否已验收、工位和产品族是否完整、标签映射是否一致、是否存在空标签/越界框、Train/Val/Test 是否源视频重叠。只有页面显示任务完成而没有真实版本文件和哈希时不能冻结。

### 13.6 训练按钮不可用

常见原因是预标仍在运行、GPU 温度过高、没有冻结数据集、已有训练任务、模型后端未安装或磁盘不足。按页面提示处理，不要绕过互斥锁或温控。RT-DETRv2、D-FINE 和 Anomalib 后端未交付时保持“待安装”。

### 13.7 VPN 或代理后局域网页打不开

为 `localhost,127.0.0.1,192.168.1.129,192.168.0.0/16` 配置 `NO_PROXY/no_proxy`，并确认浏览器没有强制把局域网 HTTP 发往 127.0.0.1:7890。代理只负责外网依赖，不应成为厂内 SOP/CVAT 的必经路径。不要为解决代理问题把 8116 或 8081 直接暴露到公网。

## 14. 数据、安全与备份要求

视频、模型权重、SQLite/WAL、账号、Token、恢复码和摄像头凭据不得进入公开 GitHub。代码仓库保存源码、脱敏配置样例、说明书和小型静态素材。原片进入受控数据卷、MinIO 或 NAS；Annotation、Dataset Version 和 Model Version 独立版本化。

服务运行时不能只复制 SQLite 主文件而遗漏 WAL。使用平台备份或 SQLite backup API，备份后执行恢复演练。删除操作保留审计事件，不静默抹除历史。对外演示截图和视频发布前再次检查账号、Token、内部人员姓名、SN、摄像头 URI 和客户敏感画面。

公网访问必须使用企业 VPN 或固定域名受控反向代理，并配置 TLS、MFA/强认证、角色权限、限流、日志和备份。安全测试前需要书面授权、目标范围、时间窗、允许手段和回滚责任；不得把渗透脚本刷入相机或 SD 卡，也不得扫描未授权设备。
