# GaussPatrol 技术方案

## 1. 任务定义

输入为园区 LiDAR、IMU、RGB-D、机器人状态、任务点位和安全边界；输出为连续定位、地图、巡检路线、速度/gait 命令、设备异常、任务完成状态和可审计报告。成功条件是：在安全约束内完成全部指定点位，零碰撞，异常有证据链，系统在感知或定位失效时停车或降级。

## 2. 总体架构

系统分为实时安全平面和异步认知平面：

1. 实时平面：驱动、时间同步、LIO、局部障碍、控制门控、急停；
2. 任务平面：全局路线、点位状态机、缺陷检测、异常确认；
3. 地图平面：占据/点云地图服务实时导航，3DGS 异步生成展示资产；
4. 评测平面：真值对齐、事件日志、指标、报告和可视化。

3DGS 和报告失败不得阻塞导航；YOLO 超时不得清空已有障碍；定位不健康时不得继续发速度。

## 3. 数据流与时间

建议所有传感器使用同一时钟域或记录硬件时间戳。LiDAR 点需要 per-point time，IMU 需要 bias/scale 标定，RGB-D 需要相机内参和深度到彩色外参。每条消息记录 `stamp/frame_id/sequence/quality`。关键监控包括消息 age、队列高水位、时间倒退、TF 可用性和处理 P95。

## 4. 定位与建图

### 4.1 第一阶段

优先采用 LIO-SAM 或 FAST-LIVO2 的原始上游实现，外包成 ROS2 component，不修改其核心优化器。选择依据：传感器兼容性、算力、环境纹理、是否需要视觉约束和团队维护能力。

### 4.2 健康门控

健康状态至少使用：匹配残差、协方差/退化方向、IMU bias、有效点数、更新 age 和轨迹跳变。健康降级分为 `OK/WARN/STOP`。`STOP` 时控制层发零速度并等待重定位或人工接管。

### 4.3 评测

以 SE(3) 对齐后的 ATE RMSE、固定时间间隔 RPE、丢帧率、重定位时间和 P95 延迟为主。当前仿真只实现二维版本，输出单位均为米。

## 5. 感知与缺陷识别

动态体检测和设备缺陷检测使用不同阈值与生命周期。动态体进入局部 costmap，需要速度估计、时间衰减和遮挡处理；设备缺陷绑定设备 ID、图像时间、位姿、模型 hash、置信度、框/mask 和人工复核状态。

真实 YOLO 训练必须按设备/日期/地点拆分数据，避免相邻帧泄漏。指标报告 AP50/AP50-95、设备级 recall、漏检率、每巡检小时误报和端到端延迟。当前 `SyntheticDefectDetector` 仅验证评测管线。

## 6. 规划与任务状态机

任务状态：`INIT→LOCALIZE→NAVIGATE→INSPECT→VERIFY→NEXT→RETURN→COMPLETE`，任何状态可进入 `SAFE_STOP`。全局规划负责点位顺序和静态地形成本，局部规划负责动态障碍和可执行速度。任务完成必须同时满足位置容差、停留时间、传感器可用和巡检证据保存。

公开基线使用八邻域 A*、动态占据重规划和 step limit；真机建议使用 Nav2 BT + planner/controller plugin，或保持相同任务 API 的自研方案。

## 7. 多地形运动控制

当前实现是地形→限速/gait 的规则控制器。真机补齐路线：

1. 获得 S10 URDF、关节/轮足控制接口、状态频率和安全限制；
2. 在 Isaac Lab 构建坡道、低摩擦、碎石高度场和外力扰动；
3. 从平地速度跟踪逐级增加地形难度；
4. domain randomization 覆盖质量、摩擦、时延、传感器噪声和推力；
5. 仿真通过后进行系留、低速、软地面、单因素真机测试；
6. 与厂商 gait 基线 A/B，对跌倒、滑移、能耗和路线时间评测。

强化学习策略不能绕过急停、姿态/关节限制或厂商底层保护。

## 8. Gaussian 地图与报告

实时导航使用占据/点云地图；3DGS 只作为异步高保真可视化和巡检证据组织。训练输入需保留相机位姿、标定和图像许可。动态目标可通过 mask 排除或分层表示，避免把人员写入静态地图。输出要绑定任务 ID、地图版本、设备异常和时间范围。

当前 `GaussianMap` 只把 range hit 累计为 PLY Gaussian surrogate，验证 schema 和可视化，不执行可微渲染训练。

## 9. 安全与失效

硬件急停独立于主计算机。软件门控覆盖：定位 age/跳变、障碍 stop distance、命令 watchdog、最大速度/角速度、地图边界、任务超时、通信断开和温度/电量。现场测试由安全员控制区域，动态人员测试从低速单人开始。

## 10. 部署建议

- ROS2 Humble/Jazzy 版本在赛前锁定；
- 组件用容器或不可变镜像，记录 commit 和依赖 lock；
- LIO/局部规划绑定高优先级 CPU，3DGS/报告低优先级异步；
- TensorRT engine 与 GPU/JetPack 版本绑定并校验 hash；
- 日志采用 rosbag2 + JSONL 事件索引，敏感图像按授权保存。

## 11. 验收门槛

仿真门槛：完成率 100%、碰撞 0、动态避障成功率 100%、所有测试通过。真机门槛在拿到赛题说明后冻结；建议至少包含路线完成率 ≥95%、零安全违规、定位与感知 P95 不超过控制预算、连续 2 小时无进程崩溃，并报告而非隐去所有失败回合。

## 12. 当前实现结论

仓库证明了接口闭环、指标计算、可视化、日志和压力对比可以运行。它没有证明 S10 全地形控制、真实缺陷 AP 或 3DGS 重建质量。下一步价值最高的工作是尽快获得 SDK/实机与现场任务定义，并招募具备轮足/四足控制和 Isaac Lab 经验的队员。
