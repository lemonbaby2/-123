05 · Pitfalls & iron rules

踩坑与铁律

这 6 条全部是本次实际踩到的，不是理论推演。前 3 条的共同点是： "看起来卡死了，其实在跑" —— 判断卡死的唯一可靠依据是 IO 计数器，不是等了多久。

PITFALL 01 · 假卡死

create_empty.py --headless 会无限空跑

脚本末尾是 while simulation_app.is_running(): sim.step()。 headless 下没有窗口可关，is_running() 恒为真 → 永久循环、 GPU 恒定 ~19%、磁盘 IO 为 0。等了 30 分钟的"卡死"其实是正常空转。 判据：IO 计数器 20 秒 delta=0 且 CPU 在涨 = 空转，不是读资源。

PITFALL 02 · 静默日志

重定向到文件必须加 python -u

Isaac 的 stdout 走 4–8 KB 块缓冲。不加 -u 时跑了 30 分钟日志仍是 0 字节，进程被 kill 时缓冲区整体丢弃，关键行 [INFO]: Setup complete... 永远看不到。

PITFALL 03 · 选卡

CUDA_VISIBLE_DEVICES=1 钉 5060 Ti

双卡机器上 Isaac Sim 不会自动选显存最大的卡。显式设 CUDA_VISIBLE_DEVICES=1 后，启动日志的 GPU 枚举表里 5060 Ti 标记为 Yes: 0（活动），4060 报 "CUDA being in bad state" 是被屏蔽的正常表现。

PITFALL 04 · 真段错误

把 Anaconda 的 Library/bin 塞进 PATH = 崩溃

为了找 ffmpeg 把 /d/Anaconda/Library/bin 加进 PATH， Isaac 启动即段错误。崩溃点在 ld-linux 动态链接器内部（空指针 +8）， 触发链是 isaacsim.robot.wheeled_robots → import osqp 的原生扩展。 ffmpeg 用绝对路径调用，绝不动 PATH。

PITFALL 05 · ROS 段错误

numpy 2.x 与 ROS 2 Humble 的 rclpy ABI 不兼容

rclpy.init() 正常，但创建节点就崩，且换 CycloneDDS 也崩 —— 说明不在中间件层。用 LD_DEBUG=libs 抓到崩溃前最后加载的是 ~/.local/.../numpy.libs/libscipy_openblas64_*.so。 PYTHONNOUSERSITE=1 回落到系统 numpy 1.21.5 后立即 NODE OK。 ROS 2 Humble 必须用 numpy < 2。

PITFALL 06 · 弱网

pip 在弱网下会无声卡死，curl 才稳

pip3 install 跑了 50 分钟后 CPU 时间 15 秒零增长、 临时目录停在 25 分钟前 —— 无声挂死。改用 curl 断点续传 （-C - --retry 8 --retry-all-errors）并行预下载 14 个 nvidia wheel，再 --no-index --find-links 离线安装。 国内唯一可用的 PyTorch 镜像是阿里云 pytorch-wheels（2.96 MB/s）。

附加发现（本次未交付，已留档）：Isaac Sim 默认 experience 在这台机器上 用独立脚本启动会段错误（isaacsim.robot.wheeled_robots 加载阶段）， 而 Isaac Lab 的 headless.rendering.kit experience 一切正常。 结论：做 standalone 脚本一律走 Isaac Lab 的 experience，别用默认的。 同时该 experience 不含 isaacsim.sensors，需要相机要另想办法。
