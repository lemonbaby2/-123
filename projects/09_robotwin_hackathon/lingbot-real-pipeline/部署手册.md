## 0.1 已验证的关键事实（勿再试错）

| 事实 | 结论 | 影响 |
|---|---|---|
| ckpt dtype | 全 F32，25.5GB | 加载峰值内存 ≈25.5GB；bf16 推理需先转 |
| `lingbotvla_cli.yaml` 位置 | 当前代码按**上三级**找（`parents[2]`） | 已打补丁：三级找不到时回退二级并告警，避免首个报错就是 FileNotFound |
| MoE 实现 | 官方 `fused`（与 ckpt 存储一致，1708 键） | `eager` 变 5056 键；已实现 fused→eager 自动拆分（108 张量），**两条路都已验证可 strict 加载** |
| `e_score_correction_bias` | persistent **buffer**（36 个，非 parameter） | 键比对必须用 `state_dict()` 而非 `named_parameters()` |
| server 输出键 | 原始键 `action`（chunk,7） | 不是 `action.arm.position`，bridge 已按此解析 |
| server 硬编码 `.cuda()` | 构造时即上卡 | CPU 冒烟必须绕开 `LingbotVLAv2Server`，直接用 `LingbotVlaV2Policy` |
| flash_attention_2 | 代码硬编码，无 flash_attn 即崩 | 已打补丁：无 CUDA/flash_attn 自动回退 eager |
| torch 版本 | 实测 2.11.0+cpu | 与 transformers 4.57.3、lerobot 0.6.1 兼容；**GPU 侧按架构选 cu 版本** |

## 0.2 硬件门槛与显卡适配（部署前必读）

### 显存：16GB 可跑，8GB 不可

| 项 | 需求 | 备注 |
|---|---|---|
| 权重 bf16 | **12.76 GB** | 6.38B × 2 byte，软件无法再压缩 |
| CUDA context + 激活 + KV | 1.2 – 1.8 GB | `use_length=25` 时取偏小值 |
| **合计** | **≈14–15 GB** | 16GB 卡余量 1–2GB；8GB 卡差 7GB |

> 量化（int8/int4）能塞进 8GB，但 VLA 动作输出对量化误差极敏感，**真机首跑不建议**。
> CPU offload 单步几十秒，做不了 30Hz 闭环。

### 主机内存：比显存更容易踩坑

官方加载流程是「CPU 建 fp32 模型 → 一次性读全部分片 → 转 bf16 上卡」，峰值 ≈51GB。
按机器内存选模式：

| 模式 | 主机内存峰值 | 开启方式 |
|---|---|---|
| 官方默认 | ~52 GB | 直接 `serve_gpu.sh` |
| 流式加载 | **~26 GB** | `--low-mem true`（`LINGBOT_LOW_MEM=1`） |
| 流式 + bf16 构建 | **~14 GB** | 再加 `LINGBOT_BF16_BUILD=1`（Windows 上有段错误风险，Linux 优先） |

失败现象对照：**Python 段错误（EXIT=139）而非 OOM 报错**，几乎都是主机内存/页面文件不够。
Windows 上 `safe_open` 对 25GB 级 mmap 会直接报 `os error 1455 页面文件太小`。

### Blackwell（RTX 50 系 / sm_120）三处必改

| 项 | 要求 | 现象 |
|---|---|---|
| torch | **cu128 及以上** | 否则 `no kernel image is available for execution` |
| flash-attn | 不装，走 sdpa/eager | 补丁已自动回退，不影响正确性 |
| MoE fused | triton 需 `>=3.3` 支持 sm_120 | 若 kernel 报错 → `--moe-layout eager`（已验证可加载） |

任何目标机器上先跑这一条，能直接给出 GO/NO-GO：

```bash
python deploy/gpu_check.py --weights <模型目录>
```

权重完整性校验（纯文件读，不 mmap，Windows 友好）：

```python
import json, struct
from pathlib import Path
D = Path(".../lingbot-vla-v2-6b-robotwin")
idx = json.loads((D/"model.safetensors.index.json").read_text())
present = set()
for shard in sorted(set(idx["weight_map"].values())):
    with open(D/shard, "rb") as f:
        n = struct.unpack("<Q", f.read(8))[0]
        h = json.loads(f.read(n))
    present |= {k for k in h if k != "__metadata__"}
print(len(idx["weight_map"]), len(present))   # 期望 1708 1708
```

> Windows 注意：`safetensors.safe_open` 会 mmap 整片文件，页面文件不够时报
> `OSError: 页面文件太小 (os error 1455)`。量大的场景改用上面的手工读头部方案。
