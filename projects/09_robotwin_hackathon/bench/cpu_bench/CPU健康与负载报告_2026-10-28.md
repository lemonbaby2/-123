| 项目 | 结果 |
|---|---|
| 满载时长 | 90.1 s |
| **计算错误** | **0** ✅ |
| 满载频率 | 3700 MHz **恒定，未掉档** ✅ |

## 四、性能：多线程扩展性（关键发现）

GEMM 2048³ FP32，走 MKL：

| 线程数 | GFLOPS | 说明 |
|---|---|---|
| 1 | 125.0 | 基准 |
| 4 | 458.1 | |
| 6 | **606.9** | |
| 8 | 429.2 | ⚠️ 反而跌 |
| **12** | **549.6**（5 轮中位数） | ✅ **最优档** |
| 14 | 624.0 | 波动大 |
| **16** | **495.9**（5 轮中位数） | ❌ **比 12 线程慢 10%** |

### 为什么会这样

`i5-12600KF` 是 **6 个性能核（12 线程）+ 4 个能效核（4 线程）** 的混合架构。

- **12 线程 = 刚好用满 6 个 P 核**（超线程），这是最优点。
- **16 线程 = 12 个 P 线程 + 4 个 E 线程**。E 核性能弱得多，
  而 GEMM 这类负载**每个线程结束都要同步** —— 整体速度被最慢的那个 E 核拖住。

所以 **线程数不是越多越好**，超过 12 就开始亏。

### 该怎么做

```bash
# Linux / WSL —— 训练脚本前加
export OMP_NUM_THREADS=12
export MKL_NUM_THREADS=12

# Windows PowerShell
$env:OMP_NUM_THREADS=12
$env:MKL_NUM_THREADS=12

# PyTorch 代码里
torch.set_num_threads(12)
```

对你的场景影响最直接的是 **DataLoader**：
`num_workers` 建议设 **4~8**（不是越多越好，worker 太多会和主进程抢 CPU，
而且每个 worker 都要反序列化数据）。

## 六、三个值得处理的点

### 1. C 盘只剩 23 GB（91%）⚠️ 最紧急

```
C:  239G  216G   23G  91%
D:  1.9T  1.7T  192G  90%
E:  931G  882G   50G  95%
```

比上次（30 GB）又少了。C 盘见底会连带影响：
虚拟内存、临时文件、软件安装、甚至 Windows 更新。
**建议尽快清理**，或者把页面文件挪到 D 盘（D 还有 192 GB）。

### 2. 内存实际跑在 DDR4-2666，不是 3200

`i5-12600KF` 官标支持 DDR4-3200，你这组 KingBank 条子配置速度是 **2666 MHz**，
实测带宽 24.4 GB/s（DDR4-2666 双通道理论 42.6 GB/s，效率 57%）。

影响：大规模数据预处理 / DataLoader 吞吐会受限。
如果能进 BIOS 开 **XMP**，且条子本身是 3200 的，能提一档；
如果条子就是 2666 的，那就只能接受了。

### 3. 虚拟化字段报 False（但 WSL2 能用）

WMI 里 `VirtualizationFirmwareEnabled` / `VMMonitorModeExtensions` 都报 `False`，
**但 WSL2 实际能跑起来**，说明这个 WMI 字段读数不准（BIOS 里 VT-x 应该是开的）。
不影响使用，记一笔而已 —— 如果哪天 WSL2 起不来，别被这个字段误导。
