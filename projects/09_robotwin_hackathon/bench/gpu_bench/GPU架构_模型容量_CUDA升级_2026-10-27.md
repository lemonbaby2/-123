## 二、两张卡的底层：不一样，差得很具体

| | **RTX 4060** | **RTX 5060 Ti** |
|---|---|---|
| 架构代号 | **Ada Lovelace** | **Blackwell** |
| 计算能力 | `sm_89` | `sm_120` |
| 发布 | 2022 | 2025 |
| 工艺 | TSMC 4N | TSMC 4NP |
| SM 数量 | 24 | 36 |
| Tensor Core | 第 4 代 | **第 5 代** |
| FP8 | ✅ | ✅ 增强 |
| **FP4 / NVFP4** | ❌ | ✅ **新增**（Blackwell 独有） |
| RT Core | 第 3 代 | 第 4 代 |
| 线程块集群（Thread Block Clusters） | ❌ | ✅ |
| 分布式共享内存（DSMEM） | ❌ | ✅ |
| 显存类型 | GDDR6 | **GDDR7** |
| 实测带宽 | 223 GB/s | **387 GB/s** |

### 对你意味着什么

**CUDA 编程模型是一样的**（grid / block / thread、全局/共享/寄存器内存层次、stream 语义）——
所以你写的 kernel 源码不用改。

**但编译产物不通用**。这是本次实测的铁证：

```
CUDA 12.6 编 sm_89  (4060)    → ✅ 编译成功
CUDA 12.6 编 sm_120 (5060 Ti) → ❌ nvcc fatal :
                                  Value 'sm_120' is not defined for option 'gpu-architecture'

CUDA 12.8 编 sm_89  (4060)    → ✅ 编译成功
CUDA 12.8 编 sm_120 (5060 Ti) → ✅ 编译成功
```

**所以**：任何编译型 CUDA 扩展（Deformable Attention、NMS、ROIPool、自定义算子）
都必须同时给出两个 arch：

```bash
export TORCH_CUDA_ARCH_LIST="8.9 12.0"     # Linux / WSL
set TORCH_CUDA_ARCH_LIST=8.9 12.0          # Windows
```

漏掉 `12.0` 就只有一个后果：4060 上好好的代码，**到 5060 Ti 上直接
`no kernel image is available for execution`，而且不会有任何编译期警告。**

## 三、CUDA Toolkit 升级：12.6 → 12.8 ✅

### 做了什么

```bash
# WSL Ubuntu-22.04 内，root 权限
apt-get update
DEBIAN_FRONTEND=noninteractive apt-get install -y --no-install-recommends cuda-toolkit-12-8
```

> 选 12.8 而不是 12.9/13.0 的理由：**和你 WSL 里 torch 的 cu128 精确匹配**。
> 用更高版本的 toolkit 编译的算子会依赖更高版本的 runtime，而 torch 自带 12.8，
> 会在运行时报 `libcudart.so.12.9: cannot open shared object file`。

### 验证结果

```
$ nvcc --version
Cuda compilation tools, release 12.8, V12.8.93

$ readlink -f /usr/local/cuda
/usr/local/cuda-12.8        # 符号链接已自动切换

# 编译 + 实跑，两张卡都过
device[1] NVIDIA GeForce RTX 5060 Ti
  compute capability : sm_120   SM count: 36   显存: 15.93 GiB
  kernel ran OK, out[0]=0.0     RESULT: OK

device[0] NVIDIA GeForce RTX 4060
  compute capability : sm_89    SM count: 24   显存: 8.00 GiB
  kernel ran OK, out[0]=0.0     RESULT: OK
```

**`sm_120` 的 kernel 已经在 5060 Ti 上真正跑起来了。**
配套验证程序在 `outputs/gpu_bench/sm_arch_check.cu`，随时可复现。

⚠️ 装上后我执行了 `wsl --shutdown`（原因见第五节）。现在 WSL 处于 Stopped，
需要时你自己启动即可，CUDA 12.8 是持久化安装的。

## 四、5060 Ti 能不能拉满：能，100%

上一版报告里我写"84.9% 满载率"，**这个结论是错的** —— 那轮我用的
GEMM 只有 4096³ 而且混了访存操作，没把 Tensor Core 压到极限。这次逐级加码重测：

| 负载 | 峰值功耗 | 满载率 | 温度 | SM 频率 |
|---|---|---|---|---|
| L1 单 stream **FP16 GEMM 8192³** | **180.1 W** | **100.0%** | 74 °C | 2580~2655 MHz |
| L2 4-stream 并行 GEMM 4096³ | 180.1 W | 100.0% | 75 °C | 2587~2692 MHz |
| L3 GEMM + 显存带宽流并发 | 130.3 W | 72.4% | 67 °C | 2790 MHz 恒定 |

```
最高峰值: 180.1 W / 180.0 W = 100.0%
✅ 可以跑满
```

**结论：5060 Ti 的供电和散热完全能撑住 180 W 满载，没有任何限制。**
（L3 反而更低，是因为并发时 GEMM 尺寸被我调小了，且带宽流拖低了 SM 效率 —— 不是卡的瓶颈。）

注意满载时 SM 频率从 2790 降到 2580 MHz，这是**正常的功耗墙行为**，
不是故障 —— 撞到 180 W 后降一点频率维持功耗上限，所有卡都这样。

## 五、⚠️ 发现一个系统级隐患：页面文件 16 GB 太小

这是本次测试**意外撞到的真问题**，会直接影响你跑任何大模型。

### 现象

跑完一轮 GPU 测试后，CUDA 直接起不来：

```
OSError: [WinError 1455] 页面文件太小，无法完成操作。
Error loading "...\torch\lib\cublas64_12.dll"
```

然后连 4 GB 显存都分配不了（`torch.cuda.mem_get_info()` 报空闲 14.72 GiB，
但 `torch.empty(4GB)` 直接 OOM）。

### 根因

| 项目 | 数值 |
|---|---|
| 页面文件 | **只有 `D:\pagefile.sys`，固定 16384 MB**，C 盘没有 |
| 自动管理 | **False**（手动固定） |
| 物理内存 | 63.8 GB |
| 当时的可用虚拟内存 | **1.4 GB**（提交上限 16 GB 快用完了） |
| 最大占用者 | `vmmem` 8.41 GB（WSL 虚拟机）、`llama-server` 1.54 GB |

CUDA 在 Windows 上加载 DLL 和建立显存映射需要**大块虚拟地址空间**，
这部分要靠页面文件支撑。提交内存一旦见底，CUDA 就起不来 ——
**跟你有多少显存、多少物理内存都没关系**。

### 已临时解决

`wsl --shutdown` 释放 vmmem 后立刻恢复：

```
可用物理内存: 15.3 GB → 29.8 GB
可用虚拟内存:  1.4 GB → 16.6 GB

[1] 5060 Ti   分配 4/8/12/14 GiB  → 全部 OK
[0] 4060      分配 4 GiB OK，8 GiB FAIL（桌面占 1.5G，正常）
```

### 但根本问题还在

16 GB 页面文件对「64 GB 内存 + 双 GPU + 跑大模型」的配置**明显不够**。
只要你同时开 WSL + IDE + 一个训练任务，就会再次撞墙。

**建议改掉**（D 盘还剩 274 GB，完全放得下）：

```powershell
# 方法 A：交给系统管理（推荐，自动按需伸缩）
# 以管理员身份运行：
$cs = Get-WmiObject Win32_ComputerSystem
$cs.AutomaticManagedPagefile = $true
$cs.Put()
# 重启生效

# 方法 B：手动固定成 32 GB（更可控）
# 控制面板 → 系统 → 高级系统设置 → 性能"设置" → 高级 → 虚拟内存"更改"
#   D:  自定义大小  初始 32768 MB / 最大 65536 MB
#   C:  系统管理的大小（或保持无分页）
# 重启生效
```

> 我这次的 PowerShell 会话不是管理员，改不了这个设置，需要你手动点一下或提权运行。
> **这不是 GPU 故障，是 Windows 虚拟内存配置问题。**

## 六、能跑什么模型（基于实测容量与算力）

### 实测基准

| | RTX 4060 | RTX 5060 Ti |
|---|---|---|
| **实际可分配显存** | **7.25 GiB**（91%） | **15.00 GiB**（94%） |
| Transformer 单层（h=4096, seq=512） | 6.71 ms / 30.7 TFLOPS | **4.19 ms / 49.2 TFLOPS** |
| 单层速度对比 | 1.0× | **1.60×** |

### 5060 Ti（15 GiB 可用）—— 主力卡

| 模型 | 精度 | 权重 | 判定 |
|---|---|---|---|
| Qwen2.5-VL-3B | FP16 | ~6 GB | ✅ 舒服 |
| Qwen2.5 / Llama-3 **7B** | Q4 | ~4.5 GB | ✅ 很舒服 |
| Qwen2.5 / Llama-3 **7B** | FP16 | ~14 GB | 🟡 勉强（KV cache 只剩 1 GB） |
| Qwen2.5 **14B** | Q4 | ~9 GB | ✅ 可以 |
| Qwen2.5 **32B** | Q4 | ~20 GB | ❌ 单卡不行，需模型并行 |
| YOLOv8 / YOLO11 全系 | FP16 | 小 | ✅ 训练 + 推理 |
| SmolVLA / OpenVLA (LoRA 微调) | BF16 | ~5~15 GB | ✅ / 🟡 |
| Stable Diffusion XL | FP16 | ~7 GB | ✅ |
| FLUX.1-dev | FP16 | ~24 GB | ❌ |
| Grounding DINO / SAM2 | FP16 | ~1~3 GB | ✅ |

### 4060（7.25 GiB 可用）—— 副卡

| 模型 | 精度 | 权重 | 判定 |
|---|---|---|---|
| Qwen2.5-VL-3B | Q4 | ~2 GB | ✅ |
| Qwen2.5 / Llama-3 7B | Q4 | ~4.5 GB | ✅ |
| 14B | Q4 | ~9 GB | ❌ 放不下 |
| YOLOv8s/m | FP16 | 小 | ✅ 训练 |
| YOLOv8l/x | FP16 | 中 | 🟡 batch 要调小 |
| Stable Diffusion 1.5 | FP16 | ~4 GB | ✅ |
| Grounding DINO / SAM2 | FP16 | ~1~3 GB | ✅ |

### 推理速度实测（7B FP16，32 层外推）

```
4060    : 单层 6.7 ms → 32 层 ≈ 215 ms/forward ≈ 4.7 forward/s
5060 Ti : 单层 4.2 ms → 32 层 ≈ 134 ms/forward ≈ 7.5 forward/s
                                          （不含 KV cache 与 attention）
```

⚠️ 这是**矩阵乘法部分**的吞吐，不是真实 decode 速度。真实 LLM 生成还要算
attention、KV cache 访存、采样，实际 tokens/s 会明显低于这个数。
但**相对关系可靠：5060 Ti 比 4060 快约 1.6 倍**。

## 八、你现在要做的（按优先级）

1. **改页面文件**（第五节的方法 A 或 B）—— 不然后面跑大模型随时会翻车。
2. **编译算子时写全架构**：`TORCH_CUDA_ARCH_LIST="8.9 12.0"`。
3. **训练显式指定 1 号卡**：`CUDA_VISIBLE_DEVICES=1` 或 `yolo ... device=1`。
4. WSL 的 CUDA 已经是 12.8 了，可以直接编译 5060 Ti 的算子。
   需要启动 WSL 时：`wsl -d Ubuntu-22.04`（注意它会占 8 GB 左右内存，
   页面文件改大后就没压力了）。
