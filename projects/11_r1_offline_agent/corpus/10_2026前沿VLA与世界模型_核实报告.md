**延迟结论要点**：
1. 3B 级流匹配 VLA 在**数据中心卡**（RTX 4090 / A100 / H100）上普遍在 27–73 ms，折算 14–36 Hz；但流匹配需要 4–10 次去噪步，动作头每步都要与 VLM 前缀做交叉注意力，这是边缘掉速的主因。（[S4][S11][S28]）
2. 到了 **Jetson 级**硬件，同一个模型会从几十 ms 掉到几百 ms：Tether 在 Jetson AGX Orin 上单体 π0.5 是 **900 ms**，改为「VLM 前缀只算一次 + past_kv 缓存 + action expert 跑 10 次」的分解式后降到 **100 ms（9.0×）**，且数学等价 cos=+1.000000。（[S29] https://docs.fastcrest.com/concepts/architecture ）
3. 「参数量小」不等于「实时」：450M 的 SmolVLA 在 8GB Orin Nano 上原生 ONNX+TRT 也只有 **5.25 Hz**，恰好卡在 5 Hz 下限，且视觉编码占了 91.2 ms。（[S20]）

## 2. 世界模型（World Model / WFM / WAM）——重点章节

> 本节对应任务中口语误写的「师姐模型」。世界模型与 VLA 的关系不是「并列的另一类基座」，而是**为 VLA 提供数据、表征、评测沙盒，或直接充当策略**，这一点决定了它几乎不可能跑在边缘。

### 2.3 世界模型在 VLA 训练 / 评测中的角色（五类，逐条标注来源）

1. **合成示教数据 / 数据引擎**：Cosmos-Predict2.5 提供 `robot/action-cond`、`robot/gr00tdream-gr1`、`robot/multiview-agibot` 等机器人专用变体，GR00T-Dreams 用生成轨迹训练 GR00T N1.5（[S30][S2]）；EnerVerse-D 用 4D Gaussian Splatting 从生成视频重建 3D 场景，作为几何约束过滤幻觉并产出高保真训练数据，含 Isaac Sim 生成的 300 万帧 / 4 万 episode 多视角数据（[S41]）。
2. **闭环策略评测沙盒（替代部分真机试错）**：GE-Sim 2.0 让策略在模型世界 rollout，由 World Judge 自动打分，筛选高质量轨迹混入行为克隆数据，真机在倒水/折毛巾/拔插头三类任务上成功率均提升；并显式强调「加入本体状态预测后与真机结果对齐更好」（[S42][S44]）。官方明确其边界：**不是刚体物理引擎，接触力/可微动力学/力控闭环仍不可直接替代 MuJoCo / Isaac**（[S43]）。
3. **直接充当策略**：1XWM 把「文本+起始帧 → 未来视频 → IDM 提取动作」当作控制回路，1X 明确把它定位为对主流 VLA 路线的替代（[S35][S36]）。
4. **在线修正已有 VLA 动作**：DynaWM 冻结基础 VLA，把 base action chunk 当「语义初稿」，用多视角历史外推目标速度并重写动作块；在 DynaGrasp-32 上对 SmolVLA / X-VLA / π0 / π0.5 微调版分别提升 7.19 / 45.31 / 1.88 / 10.94 个百分点，粗调版提升更大；消融显示去掉动作条件成功率跌 45.44%（[S38][S39]）。
5. **学更好的世界表征（而非测试时想象）**：Fast-WAM 的对照实验证明「推理时去掉未来画面生成几乎不掉点，训练时去掉视频联合训练则明显变差」，公开版 6B 模型在无机器人数据预训练下 RoboTwin 2.0 达 91.8%、LIBERO 平均 97.6%（[S23][S24]）。

### 2.4 参数量级判断：「只能在 DGX 训练、不能在边缘推理」

**硬结论：本报告核实到的世界模型，全部不具备在 32GB Jetson 上做实时闭环推理的条件。** 依据如下：

- **训练侧**：Cosmos-Predict2.5-14B 需 **p4d.24xlarge（8×A100）**；Cosmos-Transfer2.5-2B 虽只有 2.36B，仍需 **65.4 GB VRAM / 8×A100 40GB**（[S31][S32]）；Isaac Lab 3.0 明确「在 NVIDIA **DGX 级基础设施**上做大规模机器人学习」（[S7][S34]）。200M 视频片段预训练、数千小时机器人数据（GR00T N1.6 为 10k+ 小时、300K 步 @全局 batch 16384）（[S3]）属于典型 DGX/H100 集群工作量。
- **推理侧**：1XWM 厂商自报「骨干生成 5 秒实时视频需 **11 秒**，IDM 再需 **1 秒**」，规划时域仅 5 秒，且存在弱 3D 接地、物理不合理生成、需 best-of-N（8 路 rollout 把抽纸任务从 30% 提到 45%）等限制（[S35][S36]）。这是**秒级**而非毫秒级，比 VLA 的 5–10 Hz 要求慢 2 个数量级。
- 唯一把世界模型「压到边缘」的路径是**把视频生成完全从推理时移除**：Fast-WAM 靠「训练时想象、推理时跳过」把 810 ms 降到 190 ms（[S23]）；GE-Sim 2.0 靠 DMD2 步蒸馏把扩散压到 1–4 步（[S42]）。这两条本质都是**把世界模型的能力蒸馏/固化进策略**，而不是把世界模型本身搬上 Jetson。
- 反例佐证：14B 级 Cosmos-Reason2-8B 需 32GB+ VRAM、2B 版需 24GB+ VRAM（[S31]），而 32GB Jetson 是**统一内存**（还要同时跑视觉编码、动作头、控制器、OS），不存在把 8B/14B VLM 塞进去还可留出实时余量的空间。

### 3.3 明确不适用场景（精度 / 节拍 / 安全认证 / 负载）

1. **安全相关控制功能不能交给 VLA / GPU**。ISO 10218-1:2025 修订版要求安全关键功能达到 **ISO 13849-1 的 PL d / Category 3**（双通道冗余 + 高诊断覆盖率）；原文结论是「在消费级 GPU 上跑的神经网络**无法达到 PL d**——GPU 不是安全额定的，存在 bit-flip、内存错误、非确定性时序」。（[S50] https://failurefirst.org/research/reports/32-vla-safety-certification-bridge ）
2. 因此唯一合规架构是**功能通道 / 安全通道解耦**：VLA 只给轨迹提案，独立的 Kinematic Shield / Safety PLC / 安全控制器强制工作空间限制、速度上限、力阈值并否决 VLA 输出；只有安全通道需要 PL d 认证。ISO 10218 / ISO 13849 假定「确定性、可逐行审计的控制程序」，而学习策略的函数编码在数百万权重里、不可枚举、不可 FMEA（[S50][S51] https://www.evsint.com/zh-CN/embodied-ai-industrial-robotics-vla-models/ ；[S52] https://www.techniahqservice.com/robotics-news/physical-ai-safety-architectures ）。
3. **标准空窗期**：ISO/IEC CD TS 22440（AI 功能安全）仍处 Committee Draft、ISO 25785-1（双足动态稳定/跌倒）在起草、ISO 22166 未定稿；ISO 10218:2025 明确尚未覆盖「AI 驱动的涌现行为 / 神经网络安全功能」「模型 OTA 更新的供应链安全」（[S53] https://www.embodiedglobal.com/en/article/iso-10218-2025-humanoid-safety-cybersecurity-2026 ）。EU AI Act 将机器人安全组件列为高风险，高风险条款 **2026-08-02** 起适用（[S54] https://www.aiplusinfo.com/robotics-and-ai-the-role-of-artificial-intelligence-in-robots ）。
4. **节拍与精度**：VLA 输出是 50 步动作块、开环执行（π0 每 0.8s 才重推一次 [S11]），对「高节拍、亚毫米重复定位、力控/顺应控制」的确定性工位不占优；传统离线编程 + 安全PLC 仍可验证、成本更低。业界做法是把 VLA 封装在传统安全监控器内，并用 **ODD（运行设计域）+ SOTIF(ISO 21448)** 限定其允许运行的边界（[S51]）。
5. **负载 / 双足跌倒**：ISO 10218 不建模「70kg 双足机器人在行走速度下失稳」，动力丢失导致的是跌倒而非停止，现有标准无对应条款（[S53]）。
6. **可靠性回归**：生产部署普遍「冻结模型版本，仅在验证过的数据集上重训」，因为持续学习会引入静默回归；「一周二表现不同」无法支撑生产排程（[S54]）。

| **Tether (fastcrest)** | VLA 专用**部署层**（不训练、不做云推理） | `tether export`：torch→ONNX + `tether_config.json`，parity 校验默认阈值 1e-4，不达标拒发；`tether serve`：单 FastAPI 进程 + ORT-TensorRT EP，暴露 `/act`。支持 π0/π0.5/SmolVLA/GR00T N1.6/OpenVLA-7B/DreamZero；**分解式 π0.5** 把 VLM 前缀缓存 + action expert 跑 10 次，在 Jetson AGX Orin 上 **900 ms → 100 ms（9.0×）**且 cos=+1.000000。Wedges：policy router、SLO/熔断、deadline+云回退、A2C2 动作块修正、**ActionGuard（URDF 导出关节限位）+ 审计日志**。v0.9.6 起 **BSL 1.1**（2030 自动转 Apache-2.0），Pro $99/月/机器人 | [S29][S61] https://docs.fastcrest.com/ ；[S62] https://pypi.org/project/fastcrest-tether/ ；[S63] https://github.com/fastcrest/tether |
| **FluxVLA 三层部署栈** | 工程平台侧的 sim-to-real | ① 推理加速（Triton 融合核 + CUDA Graph，8 种硬件 2.31–9.64×，cos>0.99999）；② **Real-Time Chunking**（保留未完成动作块尾部作动态前缀，消除块间停顿）；③ 轨迹后处理（关节空间 MPC + Ruckig 滤波，限制加速度/加加速度）——这层正是「VLA 输出不可直接送电机」的工程落地 | [S28][S26] |

**工具链组合结论**：可行路径基本固定为
`LeRobot 数据集 → (训练/蒸馏) → ONNX 导出 + parity 校验 → TensorRT engine（FP16，DLA 只卸载卷积子图）→ 运行时分解（VLM 前缀缓存 + action expert 多步）→ 动作后处理/安全限幅 → ROS2 / 控制器`。
GGUF 路线需换成 `vla.cpp` 这类派生引擎才能承载动作头；`vLLM` 只在云端评测/离线批推理出现。（[S29][S55][S58][S28]）

### 4.2 Jetson AGX Orin 32GB 与 Orin NX 16GB 的能力差异（含对给定规格的纠错）

> **核实纠错（重要）**：任务描述中「Jetson AGX Orin 32GB（2048 CUDA、275 TOPS、204.8 GB/s）」这组数字，按 NVIDIA 官方规格实际对应的是 **AGX Orin 64GB** 模组；**AGX Orin 32GB 是 1792 CUDA 核 / 200 TOPS / 204.8 GB/s / 8 核 CPU / 15–40W**。二者不可混用。（[S64] https://developer.nvidia.com/blog/delivering-server-class-performance-at-the-edge-with-nvidia-jetson-orin/ ；[S65] https://sbcwiki.com/docs/soc-manufacturers/nvidia/orin ；[S66] https://www.nvidia.com/zh-cn/autonomous-machines/home ）

| 项目 | AGX Orin 64GB | **AGX Orin 32GB** | **Orin NX 16GB** | Orin Nano 8GB |
|---|---|---|---|---|
| AI 算力 | 275 TOPS (sparse INT8) | **200 TOPS** | **100 TOPS**（Super 模式 157） | 40 TOPS（Super 67），**无 DLA** |
| GPU | 2048 CUDA / 64 Tensor @1300MHz | **1792 CUDA / 56 Tensor @930MHz** | **1024 CUDA / 32 Tensor @918MHz** | 1024 CUDA / 32 Tensor @1020MHz |
| 内存 | 64GB LPDDR5 | **32GB LPDDR5** | **16GB LPDDR5** | 8GB LPDDR5 |
| 内存带宽 | 204.8 GB/s | **204.8 GB/s** | **102.4 GB/s** | 68.3 GB/s（Super 102） |
| CPU | 12× A78AE | 8× A78AE | 8× A78AE @2GHz | 6× A78AE |
| DLA | 2× NVDLA v2 | 2× NVDLA v2 | **2× NVDLA v2** | **无** |
| PCIe / 相机 | 4.0 ×16 / 最多 16 路 CSI | 4.0 ×16 / 最多 16 路 | 4.0 ×4 / 最多 4 路 | 3.0 ×4 / 最多 4 路 |
| 功耗 | 15–60W | 15–40W | 10–25W | 7–25W |

来源：[S64][S65][S57]（proventusnova 表格把 AGX Orin 32GB 也写成 275 TOPS/2048 CUDA，与 NVIDIA 官方博客及 sbcwiki 冲突，**本报告以官方 200 TOPS / 1792 CUDA 为准**）。

**能力差异的实质**：
- 带宽差异（204.8 vs 102.4 GB/s）比 TOPS 差异更影响 VLA 实时性；但 vla.cpp 的跨硬件 roofline 分析指出 **batch-1 VLA 推理是 compute-bound**（VLM 前缀编码 compute-bound、action expert memory-bound），所以「算力利用率」而非纯带宽才是部署杠杆，其 IMMA ladder GEMM 把 BitVLA 每步延迟降 4.5×（[S58]）。
- 三者均跑 **JetPack 6**，模块间切换是「硬件 + DTS 变更」而非软件移植（[S57]）；但 **DLA 有无**是 Orin Nano 与 NX/AGX 的功能性分界（[S56][S57]）。
- 容量硬约束：OpenVLA-OFT 在 F16 下约 14 GB，超过 8GB 预算时在该类设备「未尝试」（[S59]）；7B 模型 bf16 权重 14 GB，加 30–50% 运行时余量需 **24GB 卡**（[S17]），因此 **7B 级模型只能落在 AGX Orin 32GB/64GB，且必须量化**，Orin NX 16GB 只适合 ≤3B 且量化后的 student。
- 32GB 统一内存要同时容纳 OS、视觉编码、VLM、动作头、ROS2 与控制器；报告未核实到「3B–7B teacher 原生在 AGX Orin 32GB 上达 ≥10Hz」的官方数据。

## 5. 蒸馏可行性硬结论

### 5.1 关键实证：Shallow-π（Samsung Research，arXiv 2601.20262，2026）

这是本任务最直接可引用的「把 flow-based VLA teacher 蒸馏成边缘 student」证据（[S67] https://icsl-jeon.github.io/shallow-pi ；[S68] https://api.emergentmind.com/papers/2601.20262 ；[S69] https://labnotes.tech/blog/2x-faster-vla-inference-shallow-pi-distillation-edge-robotics ；[S70] https://test.42how.com/en/article/5e33d575-c72b-436b-82b6-c97e0b0e5ea3 ）：

- **做法**：把 π0/π0.5 的 **VLM backbone 与 flow-based action head 同时从 18 层压到 6 层**（不是只压 backbone）；student 用 TinyBERT 式从 teacher 均匀抽层初始化。
- **三项蒸馏目标**：`L_task`（标准 flow matching 真值速度）+ `L_kd`（匹配 teacher 每步去噪输出速度）+ `L_attn`（KL 对齐 **action→vision-language 交叉注意力**分布）。关键 ablation：**只对 action token 的中间层交叉注意力做蒸馏**；若对全 token attention 蒸馏会训练不稳定、成功率近零（[S68][S69]）。
- **结果**：>2× 推理加速、成功率绝对下降 **<1%**。LIBERO 上 π0.5-L6 **95% vs teacher 96%**，FLOPs 3.39T→1.30T、CUDA 推理 25.5ms→11.3ms；比从头训小 backbone 的 SmolVLA 高 8 个百分点（95% vs 87%）（[S69]）。
- **真机**：ALOHA + **Jetson Orin** 端到端延迟 **364 ms → 110 ms（≈10 Hz）**；peg-in-hole 10 次中 teacher 成功 7 次、student 10 次全成功（动态目标下更快推理反而更准）。Jetson Thor 上 RB-Y1：Shallow-π **80 ms/50 动作块** vs 原 π 130 ms，垃圾分类 SR 17/20 vs 12/20（[S67][S70]）。
- **对比基线（同一 Jetson Orin）**：原 π ≈**3 Hz**、SmolVLA ≈**5 Hz**、Shallow-π ≈**10 Hz**（[S67]）。
- **不可行的捷径**：layer-skipping（EfficientVLA / MoLE-VLA）对 flow-based VLA 无效——层间特征相似度随去噪时间步 τ 剧烈变化、相似度不能预测功能重要性，按敏感度移除超过 3 层成功率即崩溃；token 压缩（CogVLA）在现代 GPU/边缘上收益有限，因为 token 计算被并行化，而层是串行瓶颈（[S68][S69]）。

### 5.2 五个必要条件（逐条标注来源）

| 条件 | 具体要求 | 依据 |
|---|---|---|
| ① **Teacher 权重可得性** | 必须能拿到 teacher 完整权重 + 中间层 hidden state / 交叉注意力（做 `L_attn` 需要），且许可证允许派生与商用。**GR00T N1.5/N1.6 权重为 One-Way Noncommercial，蒸馏后商用不成立**；应改用 N1.7（商业许可）、π0/π0.5（openpi）、OpenVLA-OFT（MIT）、SmolVLA（Apache-2.0）；π0.6 / Gemini Robotics / 1XWM 闭源，**不可蒸馏** | [S1][S3][S7][S9][S12][S17][S20][S16][S35] |
| ② **示教数据规模** | 蒸馏不是零数据：需与 teacher 同分布的示教轨迹 + 归一化统计（q01/q99）。参照量级：OpenVLA 970k OXE episodes、π0 10,000+ 小时、GR00T N1.6 10k+ 小时 / 300K 步 @batch 16384、GR00T N1.7 20,854 小时人类第一视角视频；小样本侧 SmolVLA <30k episodes 可跑通、Gemini On-Device 宣称 50–100 示教可微调新任务、π0.5 单次运行需 50 episodes | [S10][S11][S3][S6][S18][S21][S13] |
| ③ **训练算力** | 参照下限：OpenVLA-OFT 微调 **8×A100/H100 80GB、50K–150K 步、1–2 天**；SmolVLA 20k 步单张 A100 **4–5 小时**；π0.5 完整微调 **>70 GB**、LoRA(JAX) 22.5 GB；π0 原训练 64×A100 15 天。蒸馏需 teacher 前向 + student 前向 + 三项 loss，显存与算力**高于同规模单模型微调** | [S19][S18][S13][S10] |
| ④ **动作头可否蒸馏** | **可以，但必须与 backbone 一起蒸馏，且需专门设计**。flow matching / diffusion 动作头每步都要与 VLM 前缀做 cross-attention，Shallow-π 证明「18→6 层 + cross-attention KL 蒸馏」可行且 <1% 掉点；**只压 backbone、或只做输出层 KD、或运行时 layer-skipping 都不成立** | [S67][S68][S69] |
| ⑤ **评测基准** | 需仿真 + 真机双层：LIBERO（Shallow-π 95% / OFT 97.1% / FluxVLA DiT4DiT 98.65% / π0.5 97.95%）、SimplerEnv、RoboCasa、Meta-World、CALVIN、RoboDojo（42 任务 × 2100 trials/model）、WorldArena（世界模型）；真机 ALOHA / SO-100/101 / Franka / RB-Y1；**并须做 parity 校验**（Tether 默认 1e-4、cos=+1.000000）与延迟/显存实测，不能只看成功率 | [S67][S17][S27][S28][S20][S29][S42] |

补充：**边缘达标线**可量化为「Jetson 上 ≥5–10 Hz」。已达到的公开数据点：SmolVLA ONNX 5.25 Hz @Orin Nano 8GB（[S20]）、Shallow-π ≈10 Hz @Jetson Orin（[S67]）、Tether 分解式 π0.5 100 ms/call（[S29]）、原 π0 仅 ≈3 Hz @Jetson Orin（[S67]）。

### 5.3 「在单机一晚内全部蒸馏完成」是否可能 —— 明确结论

**结论：不可能（在「从 3B–7B teacher 得到可商用、可在 32GB Jetson 上 ≥5–10Hz 实时、且通过 parity + 真机评测的 student」这个完整意义上）。** 理由逐条：

1. **单卡显存放不下 teacher+student+优化器状态**。7B teacher bf16 权重 14 GB，OFT 完整微调需 44–73.5 GB（[S17][S19]）；π0.5 完整微调 >70 GB、LoRA 也要 22.5 GB（[S13]）。单机单卡（≤24–32GB）连 3B teacher 的联合蒸馏都需大量梯度检查点/LoRA，7B 更不成立。
2. **已公开的同类训练耗时都超过一晚**。OpenVLA-OFT 在 **8×A100/H100** 上仍需 **1–2 天**；即便是最轻的 SmolVLA「单张 A100、20k 步」也要 **4–5 小时**，且那是**从头训 450M 小模型**，不是「3B–7B → student 的蒸馏」（[S19][S18]）。蒸馏额外要跑 teacher 前向与三项 loss，只会更慢。
3. **一晚能覆盖的只是一个子阶段**。可在一晚内完成的至多是：已有 teacher 权重 + 已备好示教数据 + 已切好 student 骨架的条件下，跑一次**小规模 LoRA/短步数蒸馏 + LIBERO 仿真评测**；或者用 Tether/vla.cpp 做**导出 + parity + TensorRT 编译**（这是部署而非蒸馏，Tether 明确「export 在部署时跑一次、不在热路径」，[S29]）。
4. **真机评测与合规无法压缩**。π\*0.6 的可靠性证据是「连续数小时、50 种衣物、59 个包装盒」（[S15]）；ISO 10218/13849 要求的验证、冻结版本、回归套件、ODD 定义、干预日志（[S52][S51]）都不是一晚能产出的。
5. **Shallow-π 论文未报告训练时长/训练算力**（arXiv 2601.20262 摘要与项目页均未给出），因此「蒸馏训练本身耗时」这一项**未核实**；但其结果（≈10 Hz @Jetson Orin、<1% 掉点）是**研究团队在多平台工业级实验中产出的**，不等于单机一晚可复现（[S67][S68]）。

**可在一晚内做的替代方案（务实建议）**：不蒸馏，而是**直接用已足够小的开源 student**（SmolVLA 450M / OpenVLA-OFT 量化 / GR00T N1.7 3B），走 Tether 的「分解式 + ONNX/TRT + parity 校验」路径，把工程时间花在动作分块、安全限幅、Real-Time Chunking 与真机数据采集上——DataCamp 的选型建议亦为「100 条干净示教跑 SmolVLA 几乎总能胜过 50 条脏示教跑 OpenVLA，把 60–70% 时间花在数据质控」（[S18]）。

## 7. 六条最关键硬结论

1. **世界模型（用户口语「师姐模型」）不能上边缘，只能进 DGX**：Cosmos-Transfer2.5-2B 虽仅 2.36B 仍需 65.4 GB VRAM / 8×A100，Predict2.5-14B 需 8×A100，1XWM 生成 5 秒视频要 11 秒；唯一「压到边缘」的方式是把视频生成从推理时移除（Fast-WAM 810→190 ms、GE-Sim 2.0 DMD2 压到 1–4 步），本质是**把世界模型能力固化进 VLA student**，而非搬模型本身。（[S31][S32][S35][S23][S42]）
2. **蒸馏可行，但必须 backbone 与动作头同时蒸、且专门蒸 cross-attention**：Shallow-π 把 π0/π0.5 从 18 层压到 6 层，用 L_task+L_kd+L_attn（只对 action→VLM 交叉注意力做 KL）实现 >2× 加速、<1% 掉点、Jetson Orin ≈10 Hz、364→110 ms；layer-skipping 与只压 backbone 均不成立。（[S67][S68][S69]）
3. **「单机一晚内全部蒸馏完成」不可能**：7B  teacher 完整微调需 44–73.5 GB 与 8×A100 跑 1–2 天，最轻的 450M 从头训也要单张 A100 4–5 小时；一晚最多完成「导出 + parity + TensorRT 编译」或一次短步数 LoRA 试跑，真机评测与合规验证无法压缩。（[S19][S18][S13][S29][S52]）
4. **规格纠错**：任务所述「AGX Orin 32GB = 2048 CUDA / 275 TOPS」实为 **AGX Orin 64GB**；32GB 版是 **1792 CUDA / 200 TOPS / 204.8 GB/s / 8 核 CPU**，Orin NX 16GB 是 **1024 CUDA / 100 TOPS / 102.4 GB/s / 2×DLA**，Orin Nano **无 DLA**。7B 模型 F16 约 14 GB，只能落在 32/64GB AGX 且必须量化。（[S64][S65][S57][S59]）
5. **许可证是蒸馏的前置红线**：GR00T N1.5/N1.6 权重为 NVIDIA One-Way Noncommercial（不可商用），π0.6 / Gemini Robotics / 1XWM 闭源，**这些模型蒸馏后商用均不成立**；应改用 N1.7（商业许可）、π0/π0.5（openpi）、OpenVLA-OFT（MIT）、SmolVLA（Apache-2.0）。（[S1][S3][S7][S16][S35][S17][S20]）
6. **工业「已集成」≠ VLA 直接控产线，且安全功能不得交给 GPU**：GTC 2026 官方名单（FANUC/ABB/YASKAWA/KUKA 等）集成的是 Omniverse/Isaac 虚拟调试 + Jetson 模块 + Cosmos 数据，ISO 10218-1:2025 要求安全功能达 PL d / Cat.3，而「消费级 GPU 上的神经网络无法达到 PL d」；合规架构必须是 VLA 出轨迹提案 + 独立安全 PLC 否决/限幅。（[S34][S50][S52][S53]）
